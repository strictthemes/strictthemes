# Atelier

A spare, high-fashion theme for portfolios and houses. Ivory and black, a didone at display size, and no corner rounded.

This skill is for building UI in the Atelier theme: a page, a section or a component. `DESIGN.md` decides the tokens: colors, type, spacing steps and corners. The notes below say how the theme lays a page out and which token goes where.

## Before you start

1. **Check the theme is installed.** The project should have `DESIGN.md` in its root and the Atelier variables in its global CSS. If not, run `npx shadcn@latest add https://strictthemes.com/r/atelier.json` and save https://strictthemes.com/themes/atelier/DESIGN.md as `DESIGN.md` in the project root. In a project without shadcn, use https://strictthemes.com/themes/atelier/tailwind.css instead. If the global CSS still imports a font the theme does not use (a new shadcn project imports Geist), remove that import, and uninstall its package if nothing else uses it. Keep every font import the theme's install added, also one for a style no page uses yet.
2. **Read `DESIGN.md` from start to finish.** It is the source of truth for every visual decision.
3. **Look at the project before writing code.** Use its framework, router and file layout. For controls (buttons, inputs, tabs, menus, dialogs, accordions, data tables) use the components in `components/ui`, and add a missing one with `npx shadcn@latest add <name>` rather than writing your own, unless the page brief names a plain element. Layout is plain elements with theme classes: sections, panels, figures and lists need no component.
4. **Teach `cn()` the theme's type classes.** shadcn's class merger does not know `text-display` or `text-h1`. It takes them for colors, so `cn("text-label text-muted-foreground")` silently drops one of the two, and a type class passed to a stock component does not replace its size. In a new shadcn project, `lib/utils.ts` only passes `cn` on from the `cn` package. Unless the file already holds the lines below, change it to:

   ```ts
   import { createCn } from "cn/config"

   // The theme's type classes are font sizes, not colors.
   export const cn = createCn({
     extend: {
       classGroups: {
         "font-size": [{ text: ["display", "h1", "h2", "body", "label"] }],
       },
     },
   })
   ```

   Then make every file in `components/ui` use it: where one has `import { cn } from "cn"`, change that line to import `cn` from the project's utils file (`@/lib/utils` in a default setup). Do the same for each component you add later. If the project uses `tailwind-merge` instead of the `cn` package, its components already import from the utils file: pass the same object to `extendTailwindMerge` and keep `clsx`.

## The theme in short

- **Fonts:** Bodoni Moda for headings, Hanken Grotesk for body text, Fragment Mono for labels and code.
- **Type scale** (size/weight; each class also sets line height and tracking): `text-display` 72px/500, `text-h1` 44px/500, `text-h2` 28px/500, `text-body` 16px/400, `text-label` 12px/400.
- **Font per size:** a type class does not set the font family. Headings (`<h1>` to `<h6>`) get the heading font on their own; on any other element add the font class: `font-heading` with `text-display`, `text-h1`, `text-h2`; `font-mono` with `text-label`.
- **Spacing scale**, with the Tailwind step in brackets: 4px (`1`), 8px (`2`), 16px (`4`), 32px (`8`), 64px (`16`), 128px (`32`).
- **Corners:** `rounded-none` 0px.
- **Colors (light mode):** primary #141414, on-primary #FAF8F5, secondary #E4DFD6, on-secondary #141414, tertiary #DDBBAA, on-tertiary #141414, neutral #68635C, background #FAF8F5, surface #F1EEE8, foreground #141414, border #D6D1C8, error #A32020.

The layout notes below are written around a sample organisation and its pages. If the user gave you their own product, its name, pages and content replace the sample's, and the layout, the colors and the classes stay as the notes give them.

### How Atelier pages are laid out

- **Container:** one `<div>` wraps the whole page and is the container: `mx-auto max-w-[1320px] px-4 md:px-8`, plus `text-body`. This width is the one arbitrary value allowed. Inside it sit the `<header>`, a `<main>` holding everything between the two, and the `<footer>`.
- **Grid:** a section's content sits in a grid: `grid grid-cols-1 md:grid-cols-12 md:gap-x-8`. The grid sets columns only, never `gap-y-*`: every vertical distance comes from the rhythm rule. Below `md` every grid item takes the full width. Leave the columns the page brief does not fill empty; center nothing to fill them. From `md` up every grid item gets `md:col-span-*`, because an item without one takes a single column: "columns 1–12" is `md:col-span-12`. It also gets `md:col-start-*` when it starts after column 1, and `md:col-start-1` when it must start a new row under an item that leaves room beside it; or the grid puts it in that room. An item whose columns overlap those of the item before it always starts a new row. Where a brief puts "a section's content in columns 5–12", the `<section>` is the grid and the content is one `<div>` with those column classes. Where a list "is itself the grid", the `<section>` is not a grid: the heading above the list sits directly in it at the full width.
- **Vertical rhythm:** written as a top margin on the lower element (`mt-*`), never as `space-y-*`, `gap-y-*`, a bottom margin or padding. Between a label and the one thing it names (a form label and its field, the "Size" line and its buttons, the house's name and the address in the footer): `mt-2`. Between a heading and the text under it, and between paragraphs: `mt-4`. A label line above a heading, and a label heading above its text, its `<address>` or its `<dl>`, count as headings: `mt-4` to what follows, or `mt-8` where the page brief says so. Between blocks inside a section (a paragraph and a button, two figures, a form and the text above it): `mt-8`. Between a picture and its caption: `mt-2`. Where two grid items share a row from `md` up, the second has its phone margin and `md:mt-0`, unless the page brief gives a margin from `md` up. Inside a flex row (the header, a caption line, a group of buttons) the space is the row's `gap-*` as the page brief states it.
- **Sections:** `<main>` holds a stack of `<section>` elements. The first has `mt-16`. Every other section has `mt-16 md:mt-32`: 128px between sections on a large screen, 64px on a phone. That top margin is the whole gap; sections have no padding and no borders unless the page brief gives one.
- **Header:** the `<header>` is itself the row, with `py-8`: `flex flex-col items-start gap-4 md:flex-row md:items-baseline md:justify-between`. On the left the house's name, a link to `/` in `font-heading text-h2`, styled as a header link and never marked as the current page. It is not a heading element: upright, with no weight class. On the right a `<nav>` with the `aria-label` "Main" and no classes, holding a `<ul>` with `flex flex-wrap gap-x-8 gap-y-2` of three links as labels, in this order: "Collection", "House" and "Appointment", each to the page of that name. Each brief names the current one, if any. Below `md` the links sit under the name; there is no "Menu" button. The header has no border.
- **Footer:** a `<footer>` with `mt-16 md:mt-32`, a 1px `border-border` top border and `py-8`. Inside it a grid like the one above. Columns 1–4 (`md:col-span-4`): the house's name as plain text in `font-heading text-h2`, then the atelier's address: one `<div>` with `mt-2 font-mono text-label uppercase text-muted-foreground` holding two `<p>` lines with no margin between them, `7 rue Belvèze` and `69001 Lyon`. Columns 9–12 (`md:col-start-9 md:col-span-4`, with `mt-8 md:mt-0`): a `<nav>` with the `aria-label` "Footer" holding a `<ul>` of the header's three links, in the same order, as labels, `mt-2` between items. The current page is marked here too, with `aria-current="page"` and `underline`. Under the grid, with `mt-8`, a label line in `text-muted-foreground` with the copyright, e.g. `© 2026 Maison Ardelle`.
- **Headings:** the `<h1>` is `text-h1`, and `text-display` from `md` up where the page brief says so (`text-h1 md:text-display`). An `<h2>` in the heading font is `text-h2`, and so is an `<h3>`. Nothing in the heading font is smaller than `text-h2`: a smaller heading is a label heading. Headings keep the weight their type class gives them (500); add no weight class. Sentence case, no full stop.
- **Italic:** the heading font's italic is the one flourish. Put it on one word of a heading, or on one title (a collection's name), as an `<em>` inside the heading; `<em>` is italic on its own. At most one italic per heading and at most two per page. Never set a paragraph, a label or body text in italics: a collection's name in a paragraph, a caption or a label line stays upright, even where the sample italicizes it.
- **Labels:** nav links, captions, credits, dates, sizes, look numbers, form labels, terms in a `<dl>`, and button and badge text are labels: `font-mono text-label uppercase`. The wide tracking comes with `text-label`; do not add a `tracking-*` class. Write a label as a short fragment, not a sentence. Error lines and helper text use the label's font and size but are sentences, and are not uppercased. Join the parts of a label line with ` · `. A label on its own line is a block element such as a `<p>`. Email addresses and what someone typed are never uppercased. A unit keeps its case: put `cm` in a `<span>` with `normal-case`.
- **Label headings:** a heading that is styled as a label (Details, Care, Hours) is an `<h2>` or `<h3>`, whichever keeps the heading order, with `font-mono text-label uppercase text-foreground`. Keep the `font-mono`: a heading element gets the heading font on its own.
- **Text color:** headings, label headings, body text, nav links and form labels are `text-foreground`. A button's or a badge's text color comes from its variant or its classes. Caption lines after the first, credits, dates, `<dt>` terms and helper text are `text-muted-foreground`. Paragraphs are never muted. No other text colors; blush (`tertiary`) is never a text color.
- **Measure:** a paragraph of body text is at most `max-w-md` wide (448px), however many columns it sits in. A heading may run wider.
- **Figures and prices:** a price, a size, a time or a count that stands on its own is `font-mono tabular-nums`, in `text-label` as part of a caption and in `text-body` where the page brief says so. Prices are written with the currency sign before the number and a comma for thousands: `€1,480`. A date or a time that stands on its own is a `<time>` with a `dateTime`: the opening hours and the years of a timeline and of a "Since" line. A `<time>` inside a sentence keeps the sentence's font. A date is written `Thursday 19 November 2026` (`dateTime="2026-11-19"`), a time `11:30`, a year `2014`. A year inside a name or a credit (`Autumn–Winter 2026`, `Tomas Reyl, 2026`, the copyright) is plain text.
- **Links:** a link in running text or in a caption is `text-foreground underline decoration-1 underline-offset-4 hover:text-muted-foreground`, and inherits its size and font. A link in the header or the footer is `text-foreground decoration-1 underline-offset-4 hover:underline`; the link for the current page has `aria-current="page"` and `underline`. Mark one only where the page brief names the current page. Links are never colored, and get `transition-colors duration-150`. Every link to a page of this site, a piece's page and the current page's own nav link included, points to `#`, unless the project has routes for these pages; the house's name always points to `/`. Any other link with no destination named is `#`.
- **Buttons:** the shadcn `Button` with `className="h-auto px-8 py-4 font-mono text-label font-normal uppercase"`: `font-normal` because the mono font has one weight. The default variant (black, ivory in dark mode) is for the page's main action. A second action is `variant="secondary"` (stone). In `components/ui/button.tsx`, replace that variant's stock `hover:bg-[color-mix(in_oklch,var(--secondary),var(--foreground)_5%)]` with `hover:bg-secondary/80`, once, not beside it: the 5% mix cannot be told from the resting color. A quiet action is `variant="outline"`. A button that sends a form needs `type="submit"`: this `Button` is `type="button"` unless told otherwise. A call to action that goes to another page is an `<a>` with the same classes: write `cn(buttonVariants({ variant }), "…")`, because `buttonVariants` alone does not merge classes. Do not use the `xs`, `sm` or icon sizes.
- **Button groups:** a set of buttons where one is chosen (a size) is a `role="group"` with `flex flex-wrap gap-2`, named by `aria-labelledby` pointing at the visible label above it. Each button has `className="h-auto min-w-16 px-4 py-2 font-mono text-label font-normal uppercase tabular-nums"`. The chosen one has `aria-pressed="true"`, `variant="secondary"` and `border-foreground`; the rest have `aria-pressed="false"` and `variant="outline"`. The chosen value is also written out in words in the label line above the group, so the choice is never shown by fill alone.
- **Inputs:** the shadcn `Input` and `Textarea` (`npx shadcn@latest add input textarea`) with `className="h-auto border-muted-foreground px-4 py-2 text-body md:text-body"`. They keep the fill they ship with, in dark mode too, and the stock `aria-invalid:border-destructive`. Every field has a visible `<label>` above it with `block`, tied to it with `htmlFor` and styled as a label in `text-foreground`; the field has `mt-2`. Fields follow each other with `mt-8`, on the wrapper `<div>` that holds a label, its field and its error. Optional fields say so in the label: `Note (optional)`.
- **Selects:** a choice from a short list is the shadcn `Select`; add it with `npx shadcn@latest add select`. Never a native `<select>`: the browser draws that one and its open list, and no control here keeps the browser's look. Write `<Select value={…} onValueChange={…}>` around `<SelectTrigger><SelectValue placeholder="…" /></SelectTrigger>` and a `<SelectContent>` that holds one `<SelectItem value="…">` per choice directly, with no `SelectGroup`. Nothing is chosen at first: the value starts as `null`, and the trigger shows the `placeholder` (`Choose a time`) in the muted color, which its stock `data-placeholder:text-muted-foreground` gives. The list has no empty choice. Where a choice's value is not its label, also give `Select` an `items` list of `{ value, label }`, or the trigger shows the value. `onValueChange` gets the new value, not an event, and its type allows `null`: ignore a `null`. The trigger fills its parent: set a width on an element around it, not on the trigger. It takes the same label, margin and error line as any field: the `<label>`'s `htmlFor` is the `id` on the `SelectTrigger`, which also gets `className="mt-2"` and, with an error, `aria-invalid` and `aria-describedby`; its border then turns red like an `Input`'s. Edit `components/ui/select.tsx`, once, changing the classes in the file, so that the trigger looks like an `Input` and the open list is the theme's:
  - `SelectTrigger`: replace `w-fit` with `w-full`, `border-input` with `border-muted-foreground`, `data-[size=default]:h-8` with `data-[size=default]:h-auto`, its two stock gaps (its own and the one in `*:data-[slot=select-value]:`) with `gap-2`, its stock paddings (`py-2` and the two side paddings after it) with `px-4 py-2`, its small text size with `text-body`, its `focus-visible:ring-*` classes with the outline classes of the Focus rule, and its `aria-invalid:ring-*` classes, the `dark:` one included, with `aria-invalid:ring-0`. Give the `ChevronDownIcon` in it `strokeWidth={1.5}` and add `-mr-1` to its classes: the chevron is drawn 4px inside its 16px box, so this puts its tip 16px from the border, as far as the text starts from the left one.
  - `SelectContent`: change the default `align = "center"` to `align = "start"` and `alignItemWithTrigger = true` to `alignItemWithTrigger = false`, so that the list opens under the trigger, not over it. On the popup, replace `w-(--anchor-width) min-w-36` with `max-w-(--available-width) min-w-(--anchor-width)`, which makes the list as wide as its trigger and wider only where a choice needs it, and replace `shadow-md ring-1 ring-foreground/10` with `border border-foreground`: nothing has a shadow in this theme, so a black hairline alone sets the list apart from the form under it. Its `bg-popover` (the deeper paper) stays, and it gets no padding.
  - `SelectItem`: replace its stock gap with `gap-2`, `py-1` with `py-2`, its left padding with `pl-4` (`pr-8` stays), its small text size with `text-body` and its corner class with `border-t border-border first:border-t-0`; delete the one class that starts with `not-data-[variant=destructive]:focus:`; on the `<span>` around the `CheckIcon`, replace `right-2` with `right-4 -mr-1`; give the `CheckIcon` `strokeWidth={1.5}`. The list is then ruled like a list of entries: each row runs from border to border with a hairline between rows, and its text stands under the trigger's text. The row under the pointer or the arrow keys keeps the stock grey fill (`focus:bg-accent`), and the chosen row has a black check under the trigger's chevron.
- **Date fields:** a date is picked from the shadcn `Calendar` in a `Popover` (`npx shadcn@latest add calendar popover`), never an `<input type="date">`, whose picker the browser draws. Write one component for it, `DatePicker` in `components/ui/date-picker.tsx`: its trigger carries the `Input`'s `dark:` fill classes, and those are allowed in `components/ui` only. It takes `id`, `labelId`, `value` (a `Date` or `undefined`), `onValueChange`, `className`, `aria-invalid`, `aria-describedby`, and the calendar's `disabled` and `startMonth`.
  - **Trigger:** the `PopoverTrigger`, with the `id`, the two `aria-` props and, through `cn` with the `className` after them, `flex h-auto w-full items-center justify-between gap-2 rounded-lg border border-muted-foreground bg-transparent px-4 py-2 text-left text-body transition-colors outline-none select-none focus-visible:border-ring disabled:cursor-not-allowed disabled:opacity-50 aria-invalid:border-destructive dark:bg-input/30 dark:hover:bg-input/50 dark:aria-invalid:border-destructive/50` and the four `focus-visible:outline-*` classes of the Focus rule: an `Input`'s box. In it, a `<span>` with the `id` `{id}-value` and `min-w-0`, then the `Calendar` icon of the Icons note with `shrink-0 text-muted-foreground`. The span holds the chosen day as a `<time dateTime="2026-11-19">` written as the Figures note writes a date, `Thursday 19 November 2026`, with a non-breaking space (U+00A0) in place of the two spaces after the day's number: a date too long for a narrow phone then breaks after the weekday and is never cut off, which is also why the trigger has no `whitespace-nowrap`. With no day chosen the span holds `Choose a day` in a `<span>` with `text-muted-foreground`. The trigger's `aria-labelledby` is `{labelId} {id}-value`, the visible label and then the day: named by `htmlFor` alone, a screen reader would say "Date" and not which. The field's `<label>` has that `id` and keeps its `htmlFor`; the page passes `className="mt-2"`.
  - **Popup:** `<PopoverContent align="start" className="w-auto">` around a `<div>` with a ref, which holds `<Calendar mode="single" required weekStartsOn={1} selected={value} defaultMonth={value ?? startMonth} startMonth={startMonth} disabled={disabled} onSelect={…} />`. `required` keeps a click on the chosen day from clearing it. `onSelect` hands the day to `onValueChange` and closes the popover, whose `open` the component holds in state (`open` and `onOpenChange` on the `Popover`); focus returns to the trigger by itself. Give the `PopoverContent` `initialFocus={() => ref.current?.querySelector('td button[tabindex="0"]') ?? true}`: without it the popover focuses the "previous month" arrow, not a day. The calendar gives a `Date` at local midnight: write `dateTime` from its `getFullYear()`, `getMonth()` and `getDate()`, never from `toISOString()`, which is UTC and can shift the day.
  - **`components/ui/popover.tsx`:** on the popup, replace its stock gap and padding with `gap-4 p-4`, its small text size with `text-body`, and `shadow-md ring-1 ring-foreground/10` with `border border-foreground`, as on the list of a `Select`.
  - **`components/ui/calendar.tsx`**, changing the classes in the file. On the root, replace `p-2` with `p-0` (the popover has the padding) and `[--cell-size:--spacing(7)]` with `[--cell-size:--spacing(8)]`: 32px days. In `button_previous` and `button_next`, add `hover:bg-accent dark:hover:bg-accent` after `select-none`. In `caption_label`, replace `font-medium` with `font-mono font-normal uppercase` and its small text size, the one for `captionLayout === "label"`, with `text-label`: the month is a label heading. `weekdays` becomes `flex gap-1`; in `weekday`, replace the arbitrary text size with `font-mono text-label uppercase`; in `week`, replace `mt-2` with `mt-1` and add `gap-1`: one 4px gutter across and down, which is where the focus outline fits. Delete the classes of `today`, leaving `cn(defaultClassNames.today)`: a grey fill marks today by color alone, and the day's button covers it. Give the two chevrons in `Chevron` that point left and right `strokeWidth={1.5}`.
  - **`CalendarDayButton`**, in the same file: add `ref={ref}` to its `<Button>`. The stock file makes that ref and never attaches it, and without it the arrow keys move nothing. In its classes, add `font-mono text-body tabular-nums decoration-1 underline-offset-4 hover:bg-accent dark:hover:bg-accent group-data-[today=true]/day:underline` after `border-0`, add `dark:data-[selected-single=true]:hover:bg-primary dark:data-[selected-single=true]:hover:text-primary-foreground` at the end, or in dark mode the chosen day loses its fill under the pointer, and delete the three `group-data-[focused=true]/day:` classes that end in `border-ring`, `ring-[3px]` and `ring-ring/50`: the stock glow ring. The outline that `button.tsx` already has shows on keyboard focus.
  - What this gives: a square popup of the deeper paper under the field, with a black hairline, no shadow and 16px of padding; the month as a label between two arrows; weekday names as muted labels; days as mono figures in 32px squares. The chosen day is a black square with an ivory figure (the stock `data-[selected-single=true]:bg-primary`). Today is underlined, not boxed: a black border already means "chosen" on a size button. A day under the pointer has the grey fill of a highlighted `Select` row, because the stock hover fill cannot be told from the popup's paper. Days outside the month are muted, and days that cannot be chosen are paler still. Do not turn on the month and year dropdowns, week numbers or a range: they are not restyled.
- **Errors:** an error is a line under its field with `mt-2`: `flex items-start gap-2 font-mono text-label text-destructive`, not uppercased, holding the `CircleAlert` icon (`shrink-0`, no margin) and a sentence that says what to do. The field gets `aria-invalid` and points to the line with `aria-describedby`. Fields are checked in code when the form is sent, with `noValidate` on the `<form>`, and focus moves to the first field with an error: for a `Select` or a date field, to its trigger, found by its `id`. An error line and its field's `aria-invalid` are removed when that field changes (on `input` or `change`; for a `Select` or a date field, when a value is chosen); an error that depends on a second field (a Saturday and its time) is also removed when that second field changes. Every other error stays until the next send.
- **Forms:** a form sits on the deeper paper: the `<form>` is `bg-card p-8`, with no border. The form and its confirmation are the only filled boxes on a page. The send button sits under the last field with `mt-8`.
- **Confirmations:** a message that replaces a form goes into an element with `role="status"` that is on the page from the start, empty. The form and the status element share one wrapper, and the wrapper carries the top margin, so the message stands where the form stood. The status element has no classes and no margin, so empty it takes no space; never hide it. Inside it, rendered only once there is a message, a `<div>` with `bg-card p-8`, like the form: an `<h2>` or `<h3>` in `text-h2` (whichever keeps the heading order), then with `mt-4` one or two sentences in `text-body`. A button that follows the message sits after the status element in the same wrapper, not inside it, with `mt-8`. Give the heading `tabIndex={-1}` and move focus to it, because the button that had focus is gone.
- **Badges:** at most one badge on a page, and only where the page brief asks for it: the shadcn `Badge` (`npx shadcn@latest add badge`) with `className="h-auto rounded-none border-transparent bg-tertiary px-2 py-1 font-mono text-label font-normal uppercase text-tertiary-foreground"`. One or two words, no icon.
- **Pictures:** there are no image files. A picture is a plain `<div>` with an aspect ratio (`aspect-3/4`, `aspect-4/5`, `aspect-2/3`, `aspect-4/3`: Tailwind's ratio classes, not arbitrary values), `w-full`, a fill of `bg-secondary` unless the page brief says `bg-card`, `role="img"` and an `aria-label` that describes the photograph in a sentence. Nothing is drawn inside it: no icon, no text, no gradient, no border. Every picture sits in a `<figure>` with a `<figcaption>`.
- **Caption below:** the `<figcaption>` comes under the picture with `mt-2`. It holds label lines: the first in `text-foreground` (a look number, a piece's name), the others in `text-muted-foreground` (materials, credits), each line a `<p>`, with `mt-1` between lines.
- **Caption beside:** where the page brief puts a caption beside a picture, the `<figure>` spans all twelve columns (`md:col-span-12`) and is itself a grid from `md` up: `md:grid md:grid-cols-12 md:gap-x-8`. The picture and the caption take the columns the page brief gives them, and the caption has `md:self-end md:mt-0`, so it sits at the foot of the picture. Where the caption is to the left of the picture, give both `md:row-start-1`. Below `md` the caption sits under the picture with `mt-2`, as any caption.
- **Lists of entries:** a list where the page brief gives each item a 1px top border (a timeline, a list of workshops) is a `<ul>` or `<ol>` with `list-none`, no padding, and no space between its items; each item has `border-t border-border py-4`, and the list a `border-b border-border` that closes it. Where the page brief lays an entry out in columns, the `<li>` itself carries the grid classes beside these, and its parts are the grid items.
- **Description lists:** a `<dl>` is a list of rows. Each row is a `<div>` with `grid grid-cols-3 items-baseline gap-x-4 border-t border-border py-4`: the `<dt>` is a label in `text-muted-foreground`, the `<dd>` takes the other two columns (`col-span-2`) in `text-body`. The `<dl>` has `border-b border-border`, so the last row is closed too. This holds at 375px as well.
- **Rules:** every line is 1px and `border-border`. No shadows, no blur, no gradients, no colored backgrounds behind sections.
- **Corners:** square everywhere. The stock components are already square in this theme; `rounded-none` is the only corner class, and it is needed only where these notes give it.
- **Icons:** from the project's icon set, `lucide-react`, with `size-4`, `strokeWidth={1.5}` and `aria-hidden="true"`. Use them only where the page brief or these notes name one.
- **Motion:** in the code you write, the only transition is color. Nothing moves on scroll.

## Rules

- **Colors:** only the theme's colors, through the semantic classes (`bg-background`, `text-foreground`, `bg-card`, `bg-primary`, `text-primary-foreground`, `text-muted-foreground`, `border-border` and so on). No hex, rgb or named colors in components, and no Tailwind palette classes such as `bg-blue-500` or `text-gray-600`.
- **Spacing:** padding, margin and gap use only the scale's steps (`1`, `2`, `4`, `8`, `16`, `32`) plus 0, 1px and 2px. No arbitrary values such as `p-[18px]`, and no other steps such as `p-3` or `gap-6`. `auto` margins are fine. Widths and heights such as `w-64` or `size-4` are sizes, not spacing. This applies to the code you write: a stock component keeps the spacing inside it, unless the page brief changes it.
- **Type:** every piece of text you write gets its size from one of `text-display`, `text-h1`, `text-h2`, `text-body`, `text-label`, set on the element or on a parent it inherits from. Put `text-body` on the outermost element of the page you write. No other sizes. A stock shadcn component keeps the size it ships with, unless `DESIGN.md` or the page brief gives that component its own style. A type class does not replace a weight class: where a stock component ships `font-medium` and the text should be regular, add `font-normal`.
- **Fonts:** only the theme's fonts, through `font-sans`, `font-heading` and `font-mono`. Do not add a font.
- **Corners:** only the `rounded-*` classes, which the theme already sets. No arbitrary radius. This theme has no full rounds: do not use `rounded-full`, and give a small mark a corner under half its height or none, because a box whose corner is half its height or more is a full round however it is written.
- **Contrast:** all text meets WCAG AA against its background.
- **Stock components:** a component from `components/ui`, and an `<a>` styled with `buttonVariants`, keeps the hover, pressed and disabled colors and the motion it ships with, unless the page brief changes them. They are the theme's colors under other names.
- **Counts:** a number with a noun reads right at one: "1 set", not "1 sets". Where the page brief gives the words for only one of the two, write the other the same way.
- **Sizes from data:** a height or a width that comes from data (a chart bar, a meter) is set with an inline `style`. That is the one use for an inline style.
- **Focus:** every link and control shows a 2px outline on keyboard focus: `focus-visible:outline-solid focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring`. Keep `focus-visible:outline-solid` in it: in Tailwind 4 an `outline-none` on the same element, which stock components carry, otherwise hides the outline. An element that only gets focus from code (a heading or a message with `tabIndex={-1}`) gets the same outline written with `focus:` in place of `focus-visible:` (`focus:outline-solid focus:outline-2 focus:outline-offset-2 focus:outline-ring`): after a mouse click, a browser does not match `:focus-visible` on an element that code focuses. A link, a button or a field that code focuses keeps the `focus-visible:` classes it has: after a mouse click it shows no outline, which is how a browser treats every control, and is right. A stock component that ships its own focus ring (`Button`, `buttonVariants`, `Input`, `Textarea`, `Checkbox`, `Switch`, `RadioGroupItem`, `SelectTrigger`, the day buttons of a `Calendar`, `AccordionTrigger`, the close button of a `Sheet`) must lose that ring. Do it once, in the component's file in `components/ui`, which is yours to change: replace its `focus-visible:ring-*` classes with the outline classes, and in a field replace its `aria-invalid:ring-*` classes, the `dark:` ones included, with `aria-invalid:ring-0`, or a field with an error shows a tinted ring. `Button` has two more sets. Its base classes also carry `aria-invalid:ring-*` classes: replace them with `aria-invalid:ring-0`, as in a field. Its `destructive` variant carries `focus-visible:ring-*` classes of its own, the `dark:` one included: delete them and put nothing in their place, because the base classes already give every variant the outline. Wherever this rule says replace, change the classes in the file and do not add `ring-0` beside them: an added class only wins where it comes later and passes through `cn`. The stock `focus-visible:border-ring` can stay. These ring changes go only into the files of components that this page uses and that can take focus on it: a `Badge` that is not a link keeps its ring classes. The `cn` import from the setup steps is another matter and goes into every file. A box that scrolls sideways (a code block, a wide table) gets `tabIndex={0}`, `role="region"`, an `aria-label` and the same outline, also at widths where it happens to fit. Where a focusable box touches the edges of a parent that has `overflow-hidden`, draw its outline inside it: `focus-visible:-outline-offset-2` in place of `focus-visible:outline-offset-2`.
- **Controls:** no control keeps the browser's own look, at rest or open. A choice from a list is the project's `Select`, never a native `<select>`, whose arrow and open list the browser draws. A date is picked from the project's `Calendar` in a `Popover`, never an `<input type="date">`. A checkbox, a radio button and a switch are the project's `Checkbox`, `RadioGroup` and `Switch`, never a bare `<input>`. A `Textarea` gets `resize-none`, so the browser draws no grip in its corner: the stock one already grows with its text. Add a missing one with `npx shadcn@latest add <name>`. The theme's layout notes say how it styles each one. For one they do not cover, make it match the theme's `Input`: the same height, corner, border, fill, text size and focus outline, with its icon as far from the right edge as the text is from the left, and a popup on the theme's surface with a 1px `border-border`, the theme's corner and text in the type scale. Leave no stock text size, glow ring or translucent ring on it.
- **Not allowed:** purple or multi-color gradients; emoji used as icons or bullets; glows and colored shadows.
- **Avoid:** a card inside a card.
- **Dark mode:** the page must work with the `dark` class on `<html>`. Because every color comes from a semantic class, this needs no extra code; do not write `dark:` color overrides. A new shadcn project follows the system's mode and switches on the `d` key: leave that as it is, and add no mode switch of your own.

From the theme's own do's and don'ts:

- Do give one image or one heading the whole screen.
- Do set captions and credits small, in the mono font, and let them be found.
- Do use the italic for one word or one title at a time.
- Don't round a corner, add a shadow or tint a background to make something "pop".
- Don't set long text in Bodoni: below 28px its hairlines break up.
- Don't introduce a color, size or radius that is not a token above.
