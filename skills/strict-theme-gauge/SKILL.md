# Gauge

A plain, exact theme for hardware, parts and spec sheets. Nine steel greys, dense tables, and no accent color at all.

This skill is for building UI in the Gauge theme: a page, a section or a component. `DESIGN.md` decides the tokens: colors, type, spacing steps and corners. The notes below say how the theme lays a page out and which token goes where.

## Before you start

1. **Check the theme is installed.** The project should have `DESIGN.md` in its root and the Gauge variables in its global CSS. If not, run `npx shadcn@latest add https://strictthemes.com/r/gauge.json` and save https://strictthemes.com/themes/gauge/DESIGN.md as `DESIGN.md` in the project root. In a project without shadcn, use https://strictthemes.com/themes/gauge/tailwind.css instead. If the global CSS still imports a font the theme does not use (a new shadcn project imports Geist), remove that import, and uninstall its package if nothing else uses it. Keep every font import the theme's install added, also one for a style no page uses yet.
2. **Read `DESIGN.md` from start to finish.** It is the source of truth for every visual decision.
3. **Look at the project before writing code.** Use its framework, router and file layout. For controls (buttons, inputs, tabs, menus, dialogs, accordions, data tables) use the components in `components/ui`, and add a missing one with `npx shadcn@latest add <name>` rather than writing your own, unless the page brief names a plain element. Layout is plain elements with theme classes: sections, panels, figures and lists need no component.
4. **Teach `cn()` the theme's type classes.** shadcn's class merger does not know `text-display` or `text-h1`. It takes them for colors, so `cn("text-label text-muted-foreground")` silently drops one of the two, and a type class passed to a stock component does not replace its size. In a new shadcn project, `lib/utils.ts` only passes `cn` on from the `cn` package. Unless the file already holds the lines below, change it to:

   ```ts
   import { createCn } from "cn/config"

   // The theme's type classes are font sizes, not colors.
   export const cn = createCn({
     extend: {
       classGroups: {
         "font-size": [{ text: ["display", "h1", "h2", "body", "label"] }],
       },
     },
   })
   ```

   Then make every file in `components/ui` use it: where one has `import { cn } from "cn"`, change that line to import `cn` from the project's utils file (`@/lib/utils` in a default setup). Do the same for each component you add later. If the project uses `tailwind-merge` instead of the `cn` package, its components already import from the utils file: pass the same object to `extendTailwindMerge` and keep `clsx`.

## The theme in short

- **Fonts:** Chivo for headings, Libre Franklin for body text, Roboto Mono for labels and code.
- **Type scale** (size/weight; each class also sets line height and tracking): `text-display` 48px/800, `text-h1` 32px/700, `text-h2` 20px/700, `text-body` 15px/400, `text-label` 12px/500.
- **Font per size:** a type class does not set the font family. Headings (`<h1>` to `<h6>`) get the heading font on their own; on any other element add the font class: `font-heading` with `text-display`, `text-h1`, `text-h2`; `font-mono` with `text-label`.
- **Spacing scale**, with the Tailwind step in brackets: 4px (`1`), 8px (`2`), 12px (`3`), 16px (`4`), 24px (`6`), 48px (`12`).
- **Corners:** `rounded-sm` 2px, `rounded-md` 4px, `rounded-xl` 8px (the `lg` corner in `DESIGN.md`). `rounded-lg` is 4px as well: it is shadcn's name for the base corner, the one its stock buttons and inputs use.
- **Colors (light mode):** primary #212529, on-primary #F8F9FA, secondary #E9ECEF, on-secondary #212529, tertiary #ADB5BD, on-tertiary #212529, neutral #495057, background #F8F9FA, surface #FFFFFF, foreground #212529, border #CED4DA, error #B3261E, success #1E7B4B.

The layout notes below are written around a sample organisation and its pages. If the user gave you their own product, its name, pages and content replace the sample's, and the layout, the colors and the classes stay as the notes give them.

### How Gauge pages are laid out

- **Page:** steel white, dense on purpose. The outermost element is a `<div>` with `flex min-h-svh flex-col bg-background text-body text-foreground`, holding `<header>`, `<main>` (`flex-1`) and `<footer>`.
- **Container:** the header's row, the content of `<main>` and the footer's line each sit in a centered container `<div>`, `mx-auto w-full max-w-[1280px] px-4`: a 16px gutter at every width. This width is the one arbitrary value allowed. The `<main>` element itself has `py-6`; the container inside it carries the rhythm below.
- **Today:** the sample's today is Thursday 12 November 2026, a fixed date in code, never the device clock. A page that shows no date needs no constant for it.
- **Dates and times:** a date that stands on its own (a table cell, a value, a small figure) is `12 Nov 2026`, in a `<time>` with `dateTime="2026-11-12"`. Inside a sentence a date is written out, `13 November 2026`, and is not a `<time>`, in small print too. A date that is one item of a small figure's `·` list, `updated 21 Oct 2026`, stands on its own. A time is on the 24-hour clock, `15:00`, and is a `<time>` only where it stands on its own. Dates and times take `tabular-nums` only where they are `font-mono`.
- **Sample organisation:** "Torvale Bearings Ltd", an invented supplier of industrial bearings with its works and stores in Brigholt. Prices are in pounds and exclude VAT, dimensions are in millimetres, loads in kilonewtons. The buyer filling in the forms is "Pellam Pumps Ltd". The same parts, figures and prices appear on every page; the page brief gives the ones it needs.
- **Links:** the product's name links to `/catalogue`. The nav links, in this order, are Catalogue (`/catalogue`), Compare (`/compare`), Downloads (`/downloads`) and Quote (`/quote`), the same in both navs; the page brief says which is current. Any other link without a named destination is `#`. A text link is `text-foreground underline underline-offset-4 hover:decoration-2` and inherits its size: links are the text color, so the hover thickens the underline and changes no color. Add `transition-colors duration-150`.
- **Vertical rhythm:** every vertical distance between siblings comes from a `gap-*` on their parent, a `flex flex-col` or a grid. Never use `space-y-*`. Rows and cells use padding. The only margins are the Confirmations note's. The container inside `<main>` is `flex flex-col gap-6`: the page header, then each row of panels. On a page the page brief divides into sections (each a `<section>` named by its `<h2>` with `aria-labelledby`), the container is `gap-12`, the spec's 48px between sections, and each section is `flex flex-col gap-4`. The other steps: `gap-1` between a label and the value under it; `gap-2` between a field and its helper text and error, between the options of a group, and between buttons in a row; `gap-3` between a label and its field or button group; `gap-4` inside a panel (between its heading row and its content, between groups, between the fields of a form), between panels and between grid columns. Where a page's own section gives another value, the page wins.
- **Grid:** where the page brief puts panels side by side, they are items of a 12-column grid, `grid grid-cols-1 gap-4 lg:grid-cols-12`, a single column below `lg`. "Three columns" means `lg:col-span-3`, and so on. A column of several panels is `flex flex-col gap-4`, and its last panel has `flex-1`, so the columns of a row end level.
- **Header:** a full-width `<header>` with `border-b border-border bg-card`. Its container is the row, `flex items-center gap-6 py-3`: the product's name, "Torvale", a link to `/catalogue` in `font-heading text-h2 text-foreground`, no underline; then a `<nav>` with the `aria-label` "Main" and `hidden md:block`, holding a `<ul>` with `flex gap-6` of the nav links; then, at the right end (`ml-auto`), the sales line, a `<p>` styled as a small figure, `Sales 01632 960 418`, with `hidden md:block`; and the "Menu" button of the note on menus below. Both the sales line and the button have `ml-auto`; only one of them shows at a width. A nav link is a label: the current page's link is `text-foreground underline underline-offset-4` with `aria-current="page"`, the others `text-muted-foreground hover:text-foreground`.
- **Footer:** a `<footer>` with `border-t border-border` across the full width. Its container has `py-6` and holds one small figure: "Torvale Bearings Ltd · Brigholt works · Prices exclude VAT · A demo: nothing is sold or sent."
- **Page header:** a row that is not a panel: `flex flex-wrap items-end justify-between gap-4`. On the left a stack with `gap-1`: the breadcrumb or label the page brief gives, then the `<h1>` in `text-h1`. On the right the page's actions, `flex flex-wrap gap-2`.
- **Breadcrumb:** where the page brief asks for one, it is a `<nav>` with the `aria-label` "Breadcrumb" holding an `<ol>` with `flex flex-wrap items-center gap-2`, in `font-mono text-label`: each step but the last a link in `text-muted-foreground underline underline-offset-4 hover:text-foreground`, a `/` between steps, a `<span>` in `text-muted-foreground` with `aria-hidden="true"` inside each linked step's `<li>` (`flex items-center gap-2`), after its link, so the list has one item per step, and the last step in `text-foreground` with `aria-current="page"`, not a link. Because the breadcrumb then says `page`, the header's nav link for the section it belongs to has `aria-current="true"` in place of `page`, with the same look.
- **Headings:** Chivo, sentence case, at the weight its type class sets: do not add `font-bold`, `font-semibold` or `font-medium` to a heading. A panel's or a section's `<h2>` is `text-h2`. A smaller heading inside a panel is an `<h3>` in `font-sans text-body font-bold`: body text in bold, not the heading font.
- **Panels:** a panel is a plain element with `rounded-xl border border-border bg-card p-4`, white on steel white, not the shadcn `Card`, which ships its own padding and a ring. It is `flex flex-col gap-4` when it holds a heading row and content. Never put a panel inside a panel, and never a bordered box with rounded corners inside a panel: divide a panel's parts with 1px rules (`border-t border-border`). No tinted panel: every panel is `bg-card`. A panel is a `<div>` unless the page brief names its element; on a page the page brief does not divide into sections it is never a `<section>`.
- **Panel heading:** a panel opens with a heading row, unless the page brief says it has none: `flex flex-wrap items-center justify-between gap-3`. It holds the panel's `<h2>` in `text-h2` and, at its right end, anything that belongs to the whole panel: a count, a link, a filter, a badge. A heading row that holds only the `<h2>` is still a `<div>` with these classes around it, so every panel's heading sits the same way.
- **Panels with rows:** a panel that holds a table or a list of rows has no padding of its own, no gap, and `overflow-hidden`. Its heading row is one element: the heading row's classes plus `border-b border-border px-4 py-3`, with no wrapper around it. Each row of a list has `px-4 py-3` and a 1px top border, except the first. Anything under the table inside the panel (a note, a total) is a row with `border-t border-border px-4 py-3`.
- **Labels:** table headers, field labels, the names of groups, nav links, breadcrumbs and button and badge text are labels: `font-mono text-label`, in sentence case, never `uppercase`, a short fragment and never a sentence. They are `text-muted-foreground` unless a note or the page brief gives another color; button and badge text keep their component's color.
- **Small figures:** a part number under a name, a date, a count, a file size, a reference, helper text and small print are small figures: `font-mono text-label tabular-nums text-muted-foreground`, the look of a label used for a value or a sentence. A `text-foreground` in the page brief replaces the muted color.
- **Numbers and units:** every number that stands on its own (a table cell, a value, a price) is `font-mono tabular-nums`; inside a sentence it stays in the body font. A quantity, a dimension, a load, a price and a file size are right-aligned in a table, and so is their column's header. A unit is given once, where the eye finds it: in a table it is in the column header, "Bore (mm)", and the cells hold the bare figure, `20`; beside a single value it follows the figure with a space, `20 mm`, `13.40 kN`. Prices have two decimals and a thousands comma (`1,137.80`); outside a priced column they carry the pound sign, `£2.94`. A minus sign is U+2212 (`−30 °C`). Never round a figure the buyer relies on: write the decimals the page brief gives.
- **Part numbers:** a part number is `font-mono` and written in full everywhere (`TVL-2047-RS`), never shortened or hidden behind a click. In a table's first column it is a text link in `font-mono text-body`; under a name it is a small figure.
- **Text color:** headings, body text and values are `text-foreground`. Labels, small figures and helper text are `text-muted-foreground`, and only on the page or a panel, never on a fill.
- **Measure:** a paragraph of body text is `text-foreground`, never muted, and at most `max-w-lg` wide.
- **Buttons:** the shadcn `Button` with `className="px-4 font-mono text-label"`, its stock height and corner, in sentence case; add it with `npx shadcn@latest add button` if missing. There are two looks and no others. The default variant (graphite) is for the one main action of a view, "Add to quote" or "Request a quote": at most one enabled default button on screen. Every other button is `variant="secondary"` (pale steel with graphite text): no `outline`, `ghost` or `destructive` buttons on these pages. In `components/ui/button.tsx`, replace the `secondary` variant's stock hover class, `hover:bg-[color-mix(in_oklch,var(--secondary),var(--foreground)_5%)]`, with `hover:bg-secondary/80`, once, on every page (each page has a secondary button, the "Menu" button at least), and add no hover class beside it or in a `className`. A button that sends a form needs `type="submit"`: this `Button` is `type="button"` unless told otherwise. A button that is disabled before anyone clicks it, or whose click moves focus elsewhere, uses the plain `disabled` prop. The page brief says whether any button gets `focusableWhenDisabled`; on a page where none does, `button.tsx` needs no `data-disabled:` classes. The stock `Button` keeps its `transition-all` and its nudge when pressed. A link styled as a button is an `<a>` with `cn(buttonVariants({ variant }), "px-4 font-mono text-label")`: `buttonVariants` alone does not merge classes.
- **Button groups:** a set of buttons where one is chosen (a filter) is a `role="group"` with `flex flex-wrap gap-1` and an `aria-label`. Every button in it is `variant="secondary"` with `aria-pressed` and the `className` `aria-pressed:border-foreground aria-pressed:font-bold` beside the Buttons note's classes: the chosen one, `aria-pressed="true"`, is marked by a 1px graphite border and bold text, never by a fill of its own. The stock button's `border-transparent` is what this border replaces.
- **Badges:** a badge marks a part: "New", "Made to order". It is the shadcn `Badge` (`npx shadcn@latest add badge`) in the `outline` variant with `className="h-auto rounded-sm border-transparent bg-tertiary px-2 py-1 font-mono text-label text-tertiary-foreground"`: mid steel with graphite text. The corner must be in this `className`, or the stock pill wins. One or two words, no icon. Steel is a fill only: never write `text-tertiary`.
- **Stock states:** a stock state is a status dot and a word, `inline-flex items-center gap-2 whitespace-nowrap`. The dot is `size-2 shrink-0 rounded-full` with `aria-hidden="true"`: `bg-success` for "In stock", `bg-muted-foreground` for "Low stock" and "Made to order", `bg-destructive` for "Discontinued". The word is `text-body text-foreground`. `text-body` sets its own weight, so on a row the page brief makes `font-bold` the word gets `font-bold` too. The dot is the only circle on these pages, and the green and the red appear nowhere but beside their word, except on an icon the page brief colors itself, such as a confirmation's `Check`: never show a state by color alone, never color a row, a cell or a panel.
- **Inputs:** the shadcn `Input` (`npx shadcn@latest add input`) with `className="px-2 text-body md:text-body"`, its stock height and corner: `px-2` puts its text on the same line as the text of a `Select` or a date field above or below. In `components/ui/input.tsx`, replace the class `bg-transparent` and the class `dark:bg-input/30` with `bg-card`, so a field is white on the white panel and matches the selects; `file:bg-transparent` and the `disabled:` fills stay. A quantity field is also `font-mono tabular-nums text-right` with `inputMode="numeric"`. A field is a `flex flex-col gap-3`: a visible `<label>` with `block`, styled as a label and tied to the field with `htmlFor`; then a stack with `gap-2` holding the field, any helper text (a small figure) and the error line when there is one. Name the helper text in the field's `aria-describedby`. An optional field says so in its label, "Phone (optional)"; a required one has no mark.
- **Selects:** a choice from a short list is the shadcn `Select`; add it with `npx shadcn@latest add select`. Never a native `<select>`: the browser draws that one and its open list, and no control here keeps the browser's look. Write `<Select items={…} value={…} onValueChange={…}>` around `<SelectTrigger><SelectValue /></SelectTrigger>` and a `<SelectContent>` that holds one `<SelectItem value="…">` per choice directly, with no `SelectGroup`. `items` is the list of the choices as `{ value, label }`: without it the trigger shows the value, not the label. `onValueChange` gets the new value, not an event, and its type allows `null`: ignore a `null`. The trigger fills its parent: set a width on an element around it, not on the trigger. Same label and stack as any field: the `<label>`'s `htmlFor` is the `id` on the `SelectTrigger`, and the trigger has `aria-labelledby` with the label's `id`, as well as `aria-invalid` and `aria-describedby`. Edit `components/ui/select.tsx`, once, changing the classes in the file, so that the trigger looks like an `Input` and the open list is the theme's:
  - `SelectTrigger`: replace `w-fit` with `w-full`, its two stock gaps (its own and the one in `*:data-[slot=select-value]:`) with `gap-2`, its stock paddings (the vertical one and the two side paddings after it) with `pr-1 pl-2`, its small text size with `text-body`, `bg-transparent` with `bg-card`, its `focus-visible:ring-*` classes with the outline classes of the Focus rule, and its `aria-invalid:ring-*` classes with `aria-invalid:ring-0`; delete `dark:bg-input/30`, `dark:hover:bg-input/50` and the `dark:aria-invalid:ring-*` class. Give the `ChevronDownIcon` in it `strokeWidth={1.5}`. `pr-1` is meant: the chevron is drawn 4px inside its 16px box, so its tip ends 8px from the border, as far as the text starts from the left one.
  - `SelectContent`: change the default `align = "center"` to `align = "start"` and `alignItemWithTrigger = true` to `alignItemWithTrigger = false`, so that the list opens under the trigger, not over it. On the popup, replace `w-(--anchor-width) min-w-36` with `max-w-(--available-width) min-w-(--anchor-width)`, which makes the list as wide as its trigger and wider only where a choice needs it, and replace `ring-1 ring-foreground/10` with `border border-border py-1`; its `rounded-lg` (4px, the trigger's corner), `bg-popover` and `shadow-md`, the one short shadow of a thing that floats, stay.
  - `SelectItem`: replace its stock gap with `gap-2`, its left padding with `pl-2`, its right padding with `pr-6` and its small text size with `text-body` (`py-1` stays); delete its corner class, so a row runs the full width of the list; add `data-[selected]:font-bold`, written with the brackets, since Base UI sets `data-selected` with no value; on the `<span>` around the `CheckIcon`, replace `right-2` with `right-1`; give the `CheckIcon` `strokeWidth={1.5}`. A row's text then starts under the trigger's text. The row under the pointer or the arrow keys keeps the stock grey fill (`focus:bg-accent`); the chosen row is marked as this theme marks things, in weight and by a sign, never by a color: bold text and a check in the text color under the trigger's chevron.
- **Checkboxes:** the shadcn `Checkbox` (`npx shadcn@latest add checkbox`) with `className="rounded-sm"`, the theme's 2px corner. In `components/ui/checkbox.tsx`, replace `border-input` with `border-muted-foreground`, in the one prefixed class that holds it (`…:not-data-checked:border-input`) too: the stock border is the pale steel of a panel's edge, and an empty box drawn in it can hardly be seen on white. Each option is a `<label>` with `flex items-center gap-2 text-body text-foreground` wrapping the `Checkbox` and a `<span>` with its text, so the whole line toggles it; the `Checkbox` also gets `aria-labelledby` naming that `<span>`'s `id`. A set of options is a `<div>` with `role="group"`, `aria-labelledby` naming its label (a `<p>` styled as a label), and `flex flex-col gap-2`, the label its first item.
- **Errors:** an error line is `flex items-start gap-2 font-mono text-label text-destructive`, not a label (a sentence), holding the `CircleAlert` icon (`shrink-0`) and a sentence that says what to do. The field gets `aria-invalid` and names the line in its `aria-describedby`. Fields are checked in code on submit, with `noValidate` on the `<form>`; focus then moves to the first field with an error. Render the error lines first and move focus after: set the errors in state and focus the field in an effect that runs when they change, so the field's `aria-describedby` already points at a line that exists. An error line is removed when its own field changes (on `input` or `change`); every other error stays until the next submit.
- **Confirmations:** a message after an action goes into a `role="status"` element that is on the page from the start, empty, or it may not be announced. It is never hidden, has no classes that draw or take space, and is never an item of a `gap-*` stack or row: put it in a plain `<div>` with the element above it. The message inside it, rendered only when there is one, carries the look and the space, such as `mt-3`. Where a message replaces a form, the form and the status element share that `<div>`. Where the message replaces the control that had focus, give its heading or first element `tabIndex={-1}` and move focus to it.
- **Description lists:** a list of properties is a `<dl>`. Each row is `flex items-baseline justify-between gap-3 py-2` with a 1px top border except the first: the `<dt>` a label in `text-muted-foreground`, the `<dd>` in `text-right`, `font-mono tabular-nums` when it is a figure and `text-body` when it is a phrase.
- **Tables:** the shadcn `Table` (`npx shadcn@latest add table`) with `text-body`. The header row is mono: header cells are labels in `text-muted-foreground`, keep their stock `h-10`, `font-medium` and `whitespace-nowrap` (so a header is one short line) and get `px-4`. Body and footer cells get `px-4 py-2`. Rows are divided by the stock 1px borders and keep the stock `TableRow` hover fill, also where a row does nothing; no zebra stripes and no colored rows. Cells that hold a sentence get `whitespace-normal`. A header the page brief makes `sr-only` keeps the header cell's classes and puts its words in a `<span className="sr-only">`. No `<caption>`, which would scroll away: the table's visible name is the heading above its box, and the `label` prop below repeats its words. A wide table scrolls sideways in its own box, which is fine on a phone: edit `components/ui/table.tsx` to give its scroll box `tabIndex={0}`, `role="region"`, an `aria-label` from a required `label` prop, and the focus outline drawn inside (`focus-visible:-outline-offset-2`, since a table here fills a panel that clips). A total row sits in a `<tfoot>`: the stock `TableFooter` ships a fill, a top border and `font-medium`, so give it `bg-transparent`, and each of its `TableRow`s `hover:bg-transparent`. Its top border is the one rule above the total: add no border to its cells. Its `font-medium` stays; the cells set their own weight.
- **Drawings:** a part is drawn in outline with plain elements, never an image file, an SVG or an icon: 1px lines in the text color (`border-foreground`) on the panel's white, with no fill of their own, and its dimensions in labels in `text-foreground`. Every bordered box of a drawing has square corners: no `rounded-*` class, since a bordered box with rounded corners inside a panel reads as a card inside a card. No circles, no gradients, no hatching and no shadows. Sizes that come from the part's millimetres are inline `style` widths and heights at the scale the page brief gives. The drawing has `aria-hidden="true"`; the figure's caption gives every dimension in words.
- **Icons:** from `lucide-react`, with `size-4` and `strokeWidth={1.5}`, only where the page brief or these notes name one, with `aria-hidden="true"` beside a word. Never emoji. An icon a stock component draws, such as the `Checkbox`'s check, keeps its stock stroke unless a note changes it.
- **Corners:** `rounded-sm` (2px) for badges and checkboxes, `rounded-lg` (4px, what they ship with) for buttons, inputs and selects, `rounded-xl` (8px) for panels, `rounded-full` only for the status dot, which is `size-2`, under the theme's 12px limit. No avatars and no pills.
- **Surfaces:** flat. No shadows, blur or gradients in the code you write. A stock component that floats over the page keeps the one short shadow it ships with.
- **Menus on small screens:** below `md` the nav links go behind a "Menu" button (`variant="secondary"`, `md:hidden`) with `aria-expanded` and `aria-controls`, at the right end of the header's row (`ml-auto`). It opens a second `<nav>` under the row, inside the `<header>`, also named "Main": it has `md:hidden`, the `hidden` attribute while closed, the `id` that `aria-controls` names and a full-width 1px top border; in its container, a `<ul>` with `py-2`, each link a nav link with `block py-2` added to its own classes, with no wrapper but its `<li>`. Do not use a `Sheet` or a `Dialog`. Whether the menu is open is page state, and a page that has no other state still has this one.
- **Motion:** in the code you write, only colors transition. Nothing moves on scroll. Stock components keep the motion they ship with.

## Rules

- **Colors:** only the theme's colors, through the semantic classes (`bg-background`, `text-foreground`, `bg-card`, `bg-primary`, `text-primary-foreground`, `text-muted-foreground`, `border-border` and so on). No hex, rgb or named colors in components, and no Tailwind palette classes such as `bg-blue-500` or `text-gray-600`.
- **Spacing:** padding, margin and gap use only the scale's steps (`1`, `2`, `3`, `4`, `6`, `12`) plus 0, 1px and 2px. No arbitrary values such as `p-[18px]`, and no other steps such as `p-5` or `gap-10`. `auto` margins are fine. Widths and heights such as `w-64` or `size-4` are sizes, not spacing. This applies to the code you write: a stock component keeps the spacing inside it, unless the page brief changes it. That includes the stock `gap-1.5` between a `Button`'s icon and its words: leave it, and add no gap class to the button.
- **Type:** every piece of text you write gets its size from one of `text-display`, `text-h1`, `text-h2`, `text-body`, `text-label`, set on the element or on a parent it inherits from. Put `text-body` on the outermost element of the page you write. No other sizes. A stock shadcn component keeps the size it ships with, unless `DESIGN.md` or the page brief gives that component its own style. A type class does not replace a weight class: where a stock component ships `font-medium` and the text should be regular, add `font-normal`. Text that `uppercase` sets in capitals is written in normal case in the code, also where the page brief shows it in capitals, so a screen reader does not spell it out.
- **Fonts:** only the theme's fonts, through `font-sans`, `font-heading` and `font-mono`. Do not add a font.
- **Corners:** only the `rounded-*` classes, which the theme already sets. No arbitrary radius in the code you write; a stock component's own corner classes stay. `rounded-full` only where `DESIGN.md` or the page brief names a full round, such as an avatar or a status dot. The theme allows a full round on a box up to 12px across, not larger, and a pill counts by its height.
- **Contrast:** all text meets WCAG AA against its background.
- **Stock components:** a component from `components/ui`, and an `<a>` styled with `buttonVariants`, keeps the hover, pressed and disabled colors and the motion it ships with, unless the page brief changes them, also where the layout notes give links a transition. They are the theme's colors under other names. The same holds for every other stock class that neither the notes nor the page brief name, also in a file you edit: it stays. Examples are `TableHead`'s `h-10`, `font-medium` and `whitespace-nowrap`, a `Badge`'s `gap-1` and `whitespace-nowrap`, and the `group-has-[:focus-visible]/field-label:` classes, which only act inside a shadcn `Field`. A `Button` that a stock component renders inside itself, such as the `CalendarDayButton`'s `size="icon"`, keeps its variant and size: what the notes say about button sizes is for buttons you write. Classes the notes give a stock component go in its `className` where you use it, unless they say to change its file. `TableCell`'s stock `p-2` then stays beside the `px-*` and `py-*` you pass, which is fine: those win.
- **Link transitions:** where the layout notes give every link a transition, that includes a link whose color does not change on hover, such as the name in the header: there the class does nothing, which is fine.
- **Forms:** a typed value is trimmed at both ends before it is checked and before the page shows it back (in a confirmation, a list or a summary), so a field of spaces is empty. The field itself keeps what was typed. A field's error line comes after its helper text, and its `aria-describedby` names the helper text first. A group of choices with an error (radios, checkboxes, toggle buttons) names its error line in its own `aria-describedby`, unless the page brief ties the error line to each control in it. A group that only holds fields does not: each field names its own. A radio group takes `aria-invalid` on its `RadioGroup` and a set of checkboxes on each `Checkbox`. A `<fieldset>` and a `role="group"` do not take it, so a group of toggle buttons has none.
- **Long words:** every email address and URL, the page's own included, and any name the visitor typed that the page shows back, gets `wrap-break-word` on its element or on the paragraph that holds it. One long word can run out of its box or push it wider, also in a narrow column on a wide screen. A flex item, and an item of a grid with no `grid-cols-*` class at that width, is never narrower than its longest word or its widest scroll box, so neither the class nor a scroll box keeps it in: give such an item `min-w-0`, or give the grid `grid-cols-1` below its breakpoint (`grid grid-cols-1 md:grid-cols-12`).
- **Grid columns:** an item placed in "columns 9–12" gets a span and a start at the grid's breakpoint (`md:col-span-4 md:col-start-9` where it is `md`). Write the start whenever the item does not begin right after the one before it.
- **Lists:** a list "with no markers and no padding" needs no class for it: Tailwind's base styles already remove both.
- **Dates and figures:** where the layout notes and the page brief leave a case open, a `<time>` wraps only the date or the time, not the words around it. A date or a time inside a sentence then gets no `<time>`, and nor does a copyright year. That is about the element only: whether the figure takes `tabular-nums` is a separate question. Where they leave open whether a figure in a label line, a row or a table cell takes `tabular-nums`, add it: it changes only the width of digits. Figures in running text need none. Where they ask for it but not on which element, put it on the element that holds the whole figure or label line, so that it covers every figure in it; a `<time>` inside inherits it. For a time inside a sentence, that is the `<time>` itself, not the paragraph.
- **Menus on small screens:** where the layout notes put the nav links behind a "Menu" button that opens a second `<nav>` in the header, the button is hidden from the notes' breakpoint up (`md:hidden` for `md`). Escape closes the menu while focus is on the button or in the menu, through one `onKeyDown` on the `<header>` that acts only while the menu is open, and focus then goes to the button. The second `<nav>` marks the current page's link the way the row does. It shares the row's `aria-label`, which is right, because one of the two is always hidden.
- **Counts:** a number with a noun reads right at one: "1 set", not "1 sets". Where the page brief gives the words for only one of the two, write the other the same way.
- **Sizes from data:** a height or a width that comes from data (a chart bar, a meter) is set with an inline `style`. That is the one use for an inline style.
- **Focus:** every link and control shows a 2px outline on keyboard focus: `focus-visible:outline-solid focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring`. Where a class list that the layout notes or the page brief spell out for a link, a nav link or a table's scroll box lacks them, add them to it. Keep `focus-visible:outline-solid` in it: in Tailwind 4 an `outline-none` on the same element, which stock components carry, otherwise hides the outline. An element that only gets focus from code (a heading or a message with `tabIndex={-1}`) gets the same outline written with `focus:` in place of `focus-visible:` (`focus:outline-solid focus:outline-2 focus:outline-offset-2 focus:outline-ring`): after a mouse click, a browser does not match `:focus-visible` on an element that code focuses. A link, a button or a field that code focuses keeps the `focus-visible:` classes it has: after a mouse click it shows no outline, which is how a browser treats every control, and is right. A stock component that ships its own focus ring (`Button`, `buttonVariants`, `Input`, `Textarea`, `Checkbox`, `Switch`, `RadioGroupItem`, `SelectTrigger`, the day buttons of a `Calendar`, `AccordionTrigger`, the close button of a `Sheet`) must lose that ring. Do it once, in the component's file in `components/ui`, which is yours to change: replace its `focus-visible:ring-*` classes with the outline classes, and in a field (an `Input`, a `Textarea`, a `SelectTrigger`, a `Checkbox`, a `Switch` or a `RadioGroupItem`) replace its `aria-invalid:ring-*` classes, the `dark:` ones included, with `aria-invalid:ring-0`, or a field with an error shows a tinted ring. `Button` has two more sets. Its base classes also carry `aria-invalid:ring-*` classes, the `dark:` one included: replace them with one `aria-invalid:ring-0`, as in a field. Its `aria-invalid:border-destructive` and `dark:aria-invalid:border-destructive/50` are borders and stay: what the notes say about a field's border classes is for fields. Its `destructive` variant carries `focus-visible:ring-*` classes of its own, the `dark:` one included: delete them and put nothing in their place, because the base classes already give every variant the outline. That variant's `focus-visible:border-destructive/40` is a border and stays. Wherever this rule says replace, change the classes in the file and do not add `ring-0` beside them: an added class only wins where it comes later and passes through `cn`. The stock `focus-visible:border-ring` can stay. These ring changes go only into the files of components that this page uses and that can take focus on it: a `Badge` that is not a link keeps its ring classes. So does `button.tsx` on a page with no `Button` and no `buttonVariants` link. Its other edits still follow the notes: a hover change they make "on every page" is made here too, and the `cn` import from the setup steps goes into every file. A box that scrolls sideways (a code block, a wide table) gets `tabIndex={0}`, `role="region"`, an `aria-label` and the same outline, also at widths where it happens to fit. Where a focusable box touches the edges of a parent that has `overflow-hidden`, draw its outline inside it: `focus-visible:-outline-offset-2` in place of `focus-visible:outline-offset-2`.
- **Controls:** no control keeps the browser's own look, at rest or open. A choice from a list is the project's `Select`, never a native `<select>`, whose arrow and open list the browser draws. A date is picked from the project's `Calendar` in a `Popover`, never an `<input type="date">`. A checkbox, a radio button and a switch are the project's `Checkbox`, `RadioGroup` and `Switch`, never a bare `<input>`. Add a missing one with `npx shadcn@latest add <name>`. The theme's layout notes say how it styles each one. For one they do not cover, make it match the theme's `Input`: the same height, corner, border, fill, text size and focus outline, with its icon as far from the right edge as the text is from the left, and a popup on the theme's surface with a 1px `border-border`, the theme's corner and text in the type scale. Leave no stock text size, glow ring or translucent ring on it. Every `Textarea` gets `resize-none` as well as the classes the notes give it, so the browser draws no grip in its corner. The stock one grows with its text (`field-sizing-content`), and one the page brief sizes (`field-sizing-fixed` with `rows`) keeps that size. A field that searches or filters is an `Input` with `type="search"`, which tells a screen reader it is a search box. It also gets `[&::-webkit-search-cancel-button]:appearance-none`, which hides the clear button a browser draws in it. A `Select` takes its name from its visible label in two ways: the `<label>` has the `SelectTrigger`'s `id` as its `htmlFor` (the trigger is a `<button>`, so a click on the label reaches it), and the trigger has `aria-labelledby` with the label's `id`. Base UI links only its own `Select.Label`, which `select.tsx` does not wrap (its `SelectLabel` heads a group in the open list). A date field you write as a component takes a `ref` and passes it to its trigger, so code can focus it. The stock `CalendarDayButton` makes a `ref` and never attaches it, so add `ref={ref}` to its `<Button>`, or the arrow keys move nothing. End its classes with a `dark:data-[selected-single=true]:hover:` copy of the chosen day's fill and text classes (`dark:data-[selected-single=true]:hover:bg-primary dark:data-[selected-single=true]:hover:text-primary-foreground` for the stock ones): a `hover:` class loses to the chosen day's stock `data-[selected-single=true]:` classes, but a `dark:hover:` one beats them.
- **Not allowed:** purple or multi-color gradients; emoji used as icons or bullets; glows and colored shadows.
- **Avoid:** a card inside a card.
- **Dark mode:** the page must work with the `dark` class on `<html>`. Because every color comes from a semantic class, this needs no extra code; do not write `dark:` color overrides. A new shadcn project follows the system's mode and switches on the `d` key: leave that as it is, and add no mode switch of your own.

From the theme's own do's and don'ts:

- Do give every number its unit, once, where the eye finds it.
- Do keep the page grey: a state color appears only beside its word.
- Do let a table be a table: no cards for rows of comparable figures.
- Don't add an accent color, a gradient or a tinted panel.
- Don't round a figure the buyer has to rely on, or hide a part number behind a click.
- Don't introduce a color, size or radius that is not a token above.

## Check before you finish

Build the project, then measure it against the theme with Strict Check:

```bash
npx @strictthemes/check --dist dist
```

`dist` is the folder the build wrote. Add `--path /pricing` for each page you touched other than `/`. Fix every error it lists by using a value the theme allows, and run it again until the last line starts with `Passed`. Do not mark code `strict-ignore` to get there.

Then tell the user what you built, what the check reported, and anything you could not verify.
