# Kiln

A warm, hand-made theme for shops and studios. Clay paper, a fired-terracotta accent, and type with a little wobble.

This skill is for building UI in the Kiln theme: a page, a section or a component. `DESIGN.md` decides the tokens: colors, type, spacing steps and corners. The notes below say how the theme lays a page out and which token goes where.

## Before you start

1. **Check the theme is installed.** The project should have `DESIGN.md` in its root and the Kiln variables in its global CSS. If not, run `npx shadcn@latest add https://strictthemes.com/r/kiln.json` and save https://strictthemes.com/themes/kiln/DESIGN.md as `DESIGN.md` in the project root. In a project without shadcn, use https://strictthemes.com/themes/kiln/tailwind.css instead. If the global CSS still imports a font the theme does not use (a new shadcn project imports Geist), remove that import, and uninstall its package if nothing else uses it. Keep every font import the theme's install added, also one for a style no page uses yet.
2. **Read `DESIGN.md` from start to finish.** It is the source of truth for every visual decision.
3. **Look at the project before writing code.** Use its framework, router and file layout. For controls (buttons, inputs, tabs, menus, dialogs, accordions, data tables) use the components in `components/ui`, and add a missing one with `npx shadcn@latest add <name>` rather than writing your own, unless the page brief names a plain element. Layout is plain elements with theme classes: sections, panels, figures and lists need no component.
4. **Teach `cn()` the theme's type classes.** shadcn's class merger does not know `text-display` or `text-h1`. It takes them for colors, so `cn("text-label text-muted-foreground")` silently drops one of the two, and a type class passed to a stock component does not replace its size. In a new shadcn project, `lib/utils.ts` only passes `cn` on from the `cn` package. Unless the file already holds the lines below, change it to:

   ```ts
   import { createCn } from "cn/config"

   // The theme's type classes are font sizes, not colors.
   export const cn = createCn({
     extend: {
       classGroups: {
         "font-size": [{ text: ["display", "h1", "h2", "body", "label"] }],
       },
     },
   })
   ```

   Then make every file in `components/ui` use it: where one has `import { cn } from "cn"`, change that line to import `cn` from the project's utils file (`@/lib/utils` in a default setup). Do the same for each component you add later. If the project uses `tailwind-merge` instead of the `cn` package, its components already import from the utils file: pass the same object to `extendTailwindMerge` and keep `clsx`.

## The theme in short

- **Fonts:** Bricolage Grotesque for headings, DM Sans for body text, DM Mono for labels and code.
- **Type scale** (size/weight; each class also sets line height and tracking): `text-display` 60px/700, `text-h1` 38px/700, `text-h2` 24px/600, `text-body` 16px/400, `text-label` 12px/500.
- **Font per size:** a type class does not set the font family. Headings (`<h1>` to `<h6>`) get the heading font on their own; on any other element add the font class: `font-heading` with `text-display`, `text-h1`, `text-h2`; `font-mono` with `text-label`.
- **Spacing scale**, with the Tailwind step in brackets: 4px (`1`), 8px (`2`), 16px (`4`), 24px (`6`), 40px (`10`), 80px (`20`).
- **Corners:** `rounded-sm` 2px, `rounded-md` 4px, `rounded-xl` 10px (the `lg` corner in `DESIGN.md`). `rounded-lg` is 4px as well: it is shadcn's name for the base corner, the one its stock buttons and inputs use.
- **Colors (light mode):** primary #963614, on-primary #FFF6EC, secondary #2A1D14, on-secondary #FBF6EE, tertiary #2F4A7A, on-tertiary #FBF6EE, neutral #6B5B4E, background #F4ECE1, surface #FBF6EE, foreground #2A1D14, border #DBCDBA, error #B3122D, success #2F6B3A, glaze-pale #F2EADC, glaze-dark #5A4132.

The layout notes below are written around a sample organisation and its pages. If the user gave you their own product, its name, pages and content replace the sample's, and the layout, the colors and the classes stay as the notes give them.

### How Kiln pages are laid out

- **Page:** the page is `bg-background`. Put `bg-background text-body text-foreground` on the outermost element you write.
- **Container:** `mx-auto max-w-[1120px] px-4 md:px-6`. The header's row, the footer's row and `<main>` itself carry it. This width is the one arbitrary value allowed.
- **Grid:** where the page brief gives columns, the element it names is a 12-column grid, `grid grid-cols-1 gap-x-6 md:grid-cols-12`. It sets columns and side gaps only. Below `md` the columns stack; a column that comes under another gets `mt-10 md:mt-0`. Where a part of the page brief is "a 12-column grid", its `<section>` is the grid. Where a column holds "a card", the column element itself is the card: its column classes and the card's classes go on one element.
- **Vertical rhythm:** written in one way only. `<main>` also carries `flex flex-col gap-20 pt-10 pb-20`: each section is an item of that stack, and a section never gets a top or bottom margin of its own. Inside a section, every element after the first gets its own top margin: `mt-2` between a label and what it labels, `mt-4` between a heading and its paragraph and between paragraphs, `mt-2` between a title in `text-body font-medium` and the text under it, `mt-6` between a heading and the block it opens and between form fields, `mt-10` between blocks inside a section. Never use `space-y-*`. The one other source of vertical space is the `gap-*` or `gap-y-*` of a list or grid of like items, where the page brief gives one; its items never get a top margin as well. In a column of a 12-column grid, the first element has no top margin, except the `mt-10 md:mt-0` above. A visually hidden (`sr-only`) heading takes no space, so the element after it gets no top margin for it.
- **Section heading:** a section opens with an `<h2>` in `text-h2`. Where a link belongs to the whole section, the heading and the link share a row, `flex flex-wrap items-baseline justify-between gap-x-6 gap-y-2`, and the row is the section's first element. A section with a visible `<h2>` is named by it with `aria-labelledby`; one the page brief names gets that `aria-label`; the first section of `<main>` needs no name unless the page brief gives one.
- **Headings:** a page has one `<h1>`, in `text-h1` unless the page brief says `text-display`. Headings are sentence case, with no full stop. A title in `text-body font-medium`, such as a product's name in a tile, also gets `font-sans`.
- **Header:** a `<header>` that runs the full width with a 1px bottom border (`border-b`). Inside it, one `<div>` is the container and the row: `flex flex-wrap items-center gap-x-4 gap-y-2 py-4 md:gap-x-6`. On the left the studio's name, a link to `/` in `font-heading text-h2`. Then a `<nav>` with the `aria-label` "Main" and `hidden md:block`, holding a `<ul>` with `flex gap-6` of four links, in this order: Shop (`/`), Tableware (`/tableware`), Vases (`/vases`) and Studio (`/studio`). At the right end, a wrapper `ml-auto flex items-center gap-4` holds the "Menu" button (below `md` only) and the basket link, `inline-flex items-center gap-2`: a `ShoppingBag` icon, the word "Basket" (`hidden md:inline`) and the count in brackets in `font-mono tabular-nums` (`Basket (3)`, `Basket (0)`), with an `aria-label` that says it in words ("Basket, 3 pieces", "Basket, 1 piece", "Basket, empty"). Where the count never changes on a page, keep it in a constant typed `number` (`const basketCount: number = 3`), so TypeScript still accepts the wording for 0 and 1. It goes to `/basket`, on the basket page too. The link for the current page keeps its `href` and gets `aria-current="page"` and `underline`; mark one only where the page brief names the current page. Only the main nav's links, and the basket link on the basket page, are marked this way, never the studio's name and never the footer's links. A link whose destination is not given is `#`.
- **Menus on small screens:** below `md` the nav links go behind a "Menu" button (`variant="outline"`) with `aria-expanded` and `aria-controls`, in the wrapper before the basket link. The button shows the links as a list inside the `<header>`, under its row: a second `<nav>` with `md:hidden`, the `id` that `aria-controls` names, and the `hidden` attribute while closed. It also has the `aria-label` "Main": the two are never shown at once. The second `<nav>` has a 1px top border across the full width; inside it a `<ul>` that is the container, with `py-2`, holds the same links, each a block with `py-2`. Escape closes it and moves focus to the "Menu" button. Do not use a `Sheet` or a `Dialog`.
- **Footer:** a `<footer>` that runs the full width with a 1px top border. Inside it, a `<div>` that is the container, with `py-10`, holds a row `flex flex-col gap-6 md:flex-row md:justify-between`. On the left the studio's name as plain text in `font-heading text-h2` and, with `mt-2`, the address as an `<address>` with `not-italic`, two lines split by a `<br />` (the name is not repeated): "Unit 3, Coldharbour Yard" and "Bramwick BW4 2LT". On the right a `<nav>` with the `aria-label` "Footer" holding a `<ul>` with `flex flex-col gap-2` of four links, styled as header links, in this order: Shop (`/`), Studio (`/studio`), Delivery and returns (`/delivery`) and Care of stoneware (`/care`). Under the row, with `mt-6`, a label line with the copyright, `© 2026` and the studio's name.
- **Labels:** captions, field labels, button and badge text, small print and the line of details under a product's name are labels: `font-mono text-label`. Nothing is uppercased, in the text or with a class. A label is a short fragment; only helper text and small print may be a short sentence. Other sentences are body text. A label on a line of its own is a `<p>`; one inside a line is a `<span>`.
- **Text color:** headings, body text, prices and field labels (also the `<p>` that names a button group or a quantity) are `text-foreground`. Other labels, captions and helper text are `text-muted-foreground`. A paragraph is never muted.
- **Prices and quantities:** a price is `font-mono tabular-nums` with the currency sign against the figure and two decimals (`£34.00`), in `text-foreground`, never in the primary color. A price in a tile, a list or a summary is `text-body`; the one large price on a product page and a basket's total are `text-h2 font-medium` and stay `font-mono`, in place of the rule's `font-heading` for `text-h2`. A quantity, a count and a piece's measurements are `font-mono tabular-nums` as well. Work out money in whole pence and format it with `Intl.NumberFormat("en-GB", { style: "currency", currency: "GBP" })`.
- **Measure:** a paragraph of body text is at most `max-w-lg` wide, also in a wider column or card: the space to its right stays empty.
- **Dates and times:** a date is written `6 November 2026` (`24 December` where the year is plain), a time `10:00`. Each is a `<time>` with a `dateTime` (`2026-11-06`, `10:00`), and a range is two; a year alone or "early December" is plain text. A date takes the font of the text around it (body, or mono in a label); a time is `font-mono tabular-nums`.
- **Links:** a link in running text is `text-primary underline underline-offset-4 hover:text-foreground` and inherits its size. Links in the header, the footer, a breadcrumb and a section heading's row are `text-foreground underline-offset-4 hover:underline`; this is their color and hover, not their size, so a breadcrumb's link keeps the breadcrumb's `text-label`. Every link you write gets `transition-colors duration-150`.
- **Buttons:** the shadcn `Button` with `className="h-auto px-4 py-2 font-mono text-label"`. The default variant (terracotta) is for the one thing on a screen the visitor should press; a screen shows at most one, and the page brief names it or says the page has none. Quiet actions are `variant="outline"`: the "Menu" button, the minus and plus of a quantity, "Remove", and the unchosen buttons of a group. Every other button is `variant="secondary"`. The stock secondary hover does not show in this theme: in `components/ui/button.tsx`, replace the `secondary` variant's `hover:bg-[color-mix(in_oklch,var(--secondary),var(--foreground)_5%)]` with `hover:bg-secondary/80`, once, on every page, and add nothing on the buttons. A button that sends a form needs `type="submit"`: this `Button` is `type="button"` unless told otherwise. A `w-full` button keeps the stock `whitespace-nowrap`: its label here fits at 375px. Only the minus and plus of a quantity, which their own click can disable, get `focusableWhenDisabled`, so that keyboard focus stays on them. They then carry `data-disabled` in place of `disabled`, so on a page with a quantity, and only there, add `data-disabled:pointer-events-none data-disabled:opacity-50` beside the stock `disabled:` classes in `components/ui/button.tsx`. A call to action that goes to another page is an `<a>` with the same classes: write `cn(buttonVariants({ variant }), "…")`. A button that holds only an icon is `size="icon"` with an `aria-label`; it keeps its stock size and padding, and takes none of the classes above.
- **Button groups:** a set of buttons where one is chosen (a category, a glaze, a delivery option) is a `role="group"` with `flex flex-wrap gap-2`. Its name is an `aria-label`; where the page brief asks for a visible label above the group, the label is a `<p>` and the group points to it with `aria-labelledby`. The chosen button has `aria-pressed="true"` and `variant="secondary"`; the rest have `aria-pressed="false"` and `variant="outline"`.
- **Quantity:** a `role="group"`, named as the page brief says, with `inline-flex items-center gap-2`: an `outline` button with `size="icon"`, the `Minus` icon and an `aria-label` ("One fewer"); the number in an `<output>` with `aria-live="polite"` and `inline-flex w-10 justify-center font-mono tabular-nums`, with a visually hidden "Quantity " (`sr-only`) before the figure, so a change reads "Quantity 3"; and a matching button with the `Plus` icon ("One more"). The minus is disabled at 1, the plus at the limit the page brief gives.
- **Badges:** the shadcn `Badge` (add it with `npx shadcn@latest add badge`) with `className="h-auto rounded-sm border-transparent bg-tertiary px-2 py-1 font-mono text-label text-tertiary-foreground"`: one or two words. `text-tertiary-foreground` is the theme's own color for text on denim: keep it. At most one badge on a tile. Denim is a badge fill only.
- **Inputs:** the shadcn `Input` and `Textarea` with `className="h-auto px-4 py-2 text-body md:text-body"`. In `components/ui/input.tsx` and `textarea.tsx`, replace the stock `bg-transparent` and `dark:bg-input/30` with one `bg-card`; `file:bg-transparent` in `input.tsx` stays. Every field has a visible `<label>` above it, a label in `text-foreground` with `block`, tied to it with `htmlFor`; the field has `mt-2`, or, where the page brief puts the field in a row, the row has it and the field none. Helper text under a field is a label in `text-muted-foreground` with `mt-2`.
- **Selects:** a choice from a list is the shadcn `Select`; add it with `npx shadcn@latest add select`. Never a native `<select>`: the browser draws that one and its open list, and no control here keeps the browser's look. Write `<Select items={…} value={…} onValueChange={…}>` around `<SelectTrigger><SelectValue /></SelectTrigger>` and a `<SelectContent>` that holds one `<SelectItem value="…">` per choice directly, with no `SelectGroup`. `items` is the list of the choices as `{ value, label }`: without it the trigger shows the value, not the label. `onValueChange` gets the new value, not an event, and its type allows `null`: ignore a `null`. A select that starts with nothing chosen has the value `null` and shows its prompt through `<SelectValue placeholder="…" />`, in `text-muted-foreground`, which the trigger already gives it; the prompt is not a row of the list. The trigger fills its parent: set a width on an element around it, not on the trigger; the field's `mt-2` goes on the trigger, as a `className`. It gets the same label as any field, a `<label>` tied to the `SelectTrigger` as the rules say for a `Select`, and the same error line: `aria-invalid`, `aria-describedby` and the `ref` that takes focus go on the `SelectTrigger`, and the line is removed in `onValueChange`. Edit `components/ui/select.tsx`, once, changing the classes in the file, so that the trigger looks like an `Input` and the open list is the theme's:
  - `SelectTrigger`: replace `w-fit` with `w-full`, its two stock gaps (its own and the one in `*:data-[slot=select-value]:`) with `gap-2`, `bg-transparent` with `bg-card`, its stock paddings (`py-2` and the two side paddings after it) with `px-4 py-2`, its small text size with `text-body`, its `focus-visible:ring-*` classes with the outline classes of the Focus rule, and its `aria-invalid:ring-*` classes, the `dark:` one included, with `aria-invalid:ring-0`. Delete its two fixed heights, `data-[size=default]:h-8` and `data-[size=sm]:h-7`, so that its padding and its line of body text make it as tall as an `Input`, and delete `dark:bg-input/30` and `dark:hover:bg-input/50`. Give the `ChevronDownIcon` in it `strokeWidth={1.5}` and add `-mr-1` to its classes: the chevron is drawn 4px inside its 16px box, so its tip then ends 16px from the border, as far as the text starts from the left one.
  - `SelectContent`: change the default `align = "center"` to `align = "start"` and `alignItemWithTrigger = true` to `alignItemWithTrigger = false`, so that the list opens under the trigger, not over it. On the popup, replace `w-(--anchor-width) min-w-36` with `max-w-(--available-width) min-w-(--anchor-width)`, which makes the list as wide as its trigger and wider only where a choice needs it, replace `ring-1 ring-foreground/10` with `border border-border`, and replace `shadow-md` with `shadow-sm shadow-foreground/10 dark:shadow-none`: one short shadow in the ink's brown, and none in dark mode, where the ink is pale and its shadow would be a glow. Its `rounded-lg` and `bg-popover` stay, and it gets no padding.
  - `SelectItem`: replace its stock gap with `gap-2`, its three stock paddings with `px-4 py-2` and its small text size with `text-body`; add `justify-between border-t border-border first:border-t-0`; delete `rounded-md` and the one class that starts with `not-data-[variant=destructive]:focus:`; on the `<span>` around the `CheckIcon`, replace `absolute right-2` with `-mr-1`; give the `CheckIcon` `strokeWidth={1.5}`. The list is then ruled like a description list: each row runs its full width, as tall as the trigger, with a 1px line between rows and its text under the trigger's text. The row under the pointer or the arrow keys keeps the stock fill (`focus:bg-accent`); the chosen row has a check under the trigger's chevron, in the text color, since terracotta is not for icons.
- **Errors:** an error is a line with `mt-2`: `flex items-start gap-2 font-mono text-label text-destructive`, holding the `CircleAlert` icon (`shrink-0`) and a sentence that says what to do. It sits under its field; where a field and a button share a row, it sits under the row. The field gets `aria-invalid` and points to the line with `aria-describedby`. Fields are checked in code when the form is sent, with `noValidate` on the `<form>`, and focus moves to the first field with an error. An error line is removed when its own field changes (on `input` or `change`); otherwise it stays until the next submit.
- **Confirmations:** a message that appears after an action goes into an element with `role="status"` that is on the page from the start, empty. It is never hidden (no `hidden` attribute, no `empty:hidden`), has no classes that draw or take space, and is never an item of a `gap-*` stack or row. The message is an element inside it, rendered only when there is a message, and it carries any margin: a row, `flex items-start gap-2 text-body`, with the `CircleCheck` icon in `text-success` and `mt-1`, and a sentence in `text-foreground`. A control that follows a message sits beside the status element, not in it. Where a message replaces a form, the form and the status element share one wrapper, and the wrapper carries the top margin the page brief gives, so the message stands where the form stood; give the message `tabIndex={-1}` and move focus to it.
- **Stock and state:** a state is a mark and a word, side by side: `inline-flex items-center gap-2`. A state on a line of its own is a `<p>` that carries both its top margin and `flex items-center gap-2` in place of `inline-flex`. The mark is a `size-2 shrink-0 rounded-sm` square with `aria-hidden="true"`, `bg-success` for in stock and `bg-muted-foreground` for made to order or sold out; the word is a label in `text-foreground`. Never show a state by color alone, and never put text on `bg-success`.
- **Cards:** a card is a plain element with `rounded-xl border bg-card p-6`. Do not use the shadcn `Card`. Never put a card in a card; divide its parts with 1px borders.
- **Product tiles:** a grid of tiles is a `<ul>` with `grid grid-cols-2 gap-x-4 gap-y-10 md:grid-cols-3 md:gap-x-6 lg:grid-cols-4`. Each tile is an `<li>` holding one `<a>` to the piece, with `group flex h-full flex-col overflow-hidden rounded-xl border bg-card`: the picture at its top with a 1px bottom border and no corners of its own, then the text part with `flex flex-1 flex-col p-4`. The `<a>` takes the link transition like every link and no color class: its text stays `text-foreground`. The text part holds the piece's name as an `<h3>` in `font-sans text-body font-medium underline-offset-4 group-hover:underline` (the tile's hover), with `mt-1` its glaze as a label in `text-muted-foreground` with `flex-1` (`Ash glaze`; the `flex-1` puts the price row at the foot of the tile, so a name that wraps does not lower its price below its neighbours'), and with `mt-2` a row `flex flex-wrap items-center justify-between gap-2` holding the price and, where there is one, the badge. The tile's link draws the focus outline inside it (`focus-visible:-outline-offset-2`). A piece's address is `/tableware/` (or `/vases/`) and its name in lower case, each run of other characters than letters and figures made one hyphen, none at the ends: `/tableware/tumbler-set-of-two`.
- **Pictures:** there are no image files. A picture of a piece is a plain element with `role="img"` and an `aria-label` that says what it shows, in a fixed aspect ratio (`aspect-square` or `aspect-4/5`), `bg-muted` (a theme color, as every semantic class is), with `flex items-center justify-center`. Inside it, the piece is drawn as one plain element with `border border-foreground/60` and square corners (`/60`, not less: a pale fill is almost the frame's color, so the outline alone must reach 3:1) (no `rounded-*`): `bg-glaze-pale` for a pale glaze (Ash, Oat), `bg-glaze-dark` for a dark one (Iron, Slate). Both keep their color in dark mode. Its size: `h-1/2 w-2/5` for a tall piece (a mug, a cup, a beaker, a tumbler, a jug, a vase), `h-1/4 w-3/5` for a bowl, `h-1/6 w-3/4` for a plate or a platter. In a tile the picture has `aria-hidden="true"` in place of `role="img"`. A picture that stands on its own (not in a tile or a basket line) has `rounded-xl border` and is a `<figure>` with a `<figcaption>` under it with `mt-2`, a label in `text-muted-foreground`.
- **Description lists:** details and hours are a `<dl>`. Each row is a `<div>` with a 1px top border and `py-2`, `grid grid-cols-3 items-baseline gap-x-4`: the `<dt>` is a label in `text-muted-foreground`, the `<dd>` is `col-span-2` in `text-body`. The last row also has a 1px bottom border: give every row `border-t last:border-b`.
- **Avatars:** `flex size-10 shrink-0 items-center justify-center rounded-full border bg-card`, with the person's initials centered in it in `font-heading text-body`, and `aria-hidden="true"`.
- **Icons:** from `lucide-react`, with `size-4` and `strokeWidth={1.5}`, only where the page brief or these notes name one. An icon beside a word has `aria-hidden="true"`; an icon that stands alone sits in a button with an `aria-label`.
- **Corners:** `rounded-sm` (2px) for badges and state marks, `rounded-lg` (4px, the stock corner) for buttons, inputs and selects, `rounded-xl` (10px) for cards, tiles and pictures, `rounded-full` only for avatars. A drawn piece has square corners. No pills.
- **Primary color:** terracotta is never for any fill but the default button, nor for a heading, a price, an icon or a border. The focus color (`ring`) is terracotta too: the focus outline and a field's stock `focus-visible:border-ring` stay.
- **Surfaces:** flat. No shadows, no blur and no gradients in the code you write. A stock component that floats keeps one short shadow; the Selects note gives the one for a select's list.
- **Motion:** in the code you write, the only transition is color. Nothing moves on scroll or is sticky. Stock components keep the motion they ship with.

## Rules

- **Colors:** only the theme's colors, through the semantic classes (`bg-background`, `text-foreground`, `bg-card`, `bg-primary`, `text-primary-foreground`, `text-muted-foreground`, `border-border` and so on). No hex, rgb or named colors in components, and no Tailwind palette classes such as `bg-blue-500` or `text-gray-600`.
- **Spacing:** padding, margin and gap use only the scale's steps (`1`, `2`, `4`, `6`, `10`, `20`) plus 0, 1px and 2px. No arbitrary values such as `p-[18px]`, and no other steps such as `p-3` or `gap-5`. `auto` margins are fine. Widths and heights such as `w-64` or `size-4` are sizes, not spacing. This applies to the code you write: a stock component keeps the spacing inside it, unless the page brief changes it. That includes the stock `gap-1.5` between a `Button`'s icon and its words: leave it, and add no gap class to the button.
- **Type:** every piece of text you write gets its size from one of `text-display`, `text-h1`, `text-h2`, `text-body`, `text-label`, set on the element or on a parent it inherits from. Put `text-body` on the outermost element of the page you write. No other sizes. A stock shadcn component keeps the size it ships with, unless `DESIGN.md` or the page brief gives that component its own style. A type class does not replace a weight class: where a stock component ships `font-medium` and the text should be regular, add `font-normal`. Text that `uppercase` sets in capitals is written in normal case in the code, also where the page brief shows it in capitals, so a screen reader does not spell it out.
- **Fonts:** only the theme's fonts, through `font-sans`, `font-heading` and `font-mono`. Do not add a font.
- **Corners:** only the `rounded-*` classes, which the theme already sets. No arbitrary radius in the code you write; a stock component's own corner classes stay. `rounded-full` only where `DESIGN.md` or the page brief names a full round, such as an avatar or a status dot. The theme allows a full round on a box up to 64px across, not larger, and a pill counts by its height.
- **Contrast:** all text meets WCAG AA against its background.
- **Stock components:** a component from `components/ui`, and an `<a>` styled with `buttonVariants`, keeps the hover, pressed and disabled colors and the motion it ships with, unless the page brief changes them, also where the layout notes give links a transition. They are the theme's colors under other names. The same holds for every other stock class that neither the notes nor the page brief name, also in a file you edit: it stays. Examples are `TableHead`'s `h-10`, `font-medium` and `whitespace-nowrap`, a `Badge`'s `gap-1` and `whitespace-nowrap`, and the `group-has-[:focus-visible]/field-label:` classes, which only act inside a shadcn `Field`. A `Button` that a stock component renders inside itself, such as the `CalendarDayButton`'s `size="icon"`, keeps its variant and size: what the notes say about button sizes is for buttons you write. Classes the notes give a stock component go in its `className` where you use it, unless they say to change its file. `TableCell`'s stock `p-2` then stays beside the `px-*` and `py-*` you pass, which is fine: those win.
- **Link transitions:** where the layout notes give every link a transition, that includes a link whose color does not change on hover, such as the name in the header: there the class does nothing, which is fine.
- **Forms:** a typed value is trimmed at both ends before it is checked and before the page shows it back (in a confirmation, a list or a summary), so a field of spaces is empty. The field itself keeps what was typed. A field's error line comes after its helper text, and its `aria-describedby` names the helper text first. A group of choices with an error (radios, checkboxes, toggle buttons) names its error line in its own `aria-describedby`, unless the page brief ties the error line to each control in it. A group that only holds fields does not: each field names its own. A radio group takes `aria-invalid` on its `RadioGroup` and a set of checkboxes on each `Checkbox`. A `<fieldset>` and a `role="group"` do not take it, so a group of toggle buttons has none.
- **Long words:** every email address and URL, the page's own included, and any name the visitor typed that the page shows back, gets `wrap-break-word` on its element or on the paragraph that holds it. One long word can run out of its box or push it wider, also in a narrow column on a wide screen. A flex item, and an item of a grid with no `grid-cols-*` class at that width, is never narrower than its longest word or its widest scroll box, so neither the class nor a scroll box keeps it in: give such an item `min-w-0`, or give the grid `grid-cols-1` below its breakpoint (`grid grid-cols-1 md:grid-cols-12`).
- **Grid columns:** an item placed in "columns 9–12" gets a span and a start at the grid's breakpoint (`md:col-span-4 md:col-start-9` where it is `md`). Write the start whenever the item does not begin right after the one before it.
- **Lists:** a list "with no markers and no padding" needs no class for it: Tailwind's base styles already remove both.
- **Dates and figures:** where the layout notes and the page brief leave a case open, a `<time>` wraps only the date or the time, not the words around it. A date or a time inside a sentence then gets no `<time>`, and nor does a copyright year. That is about the element only: whether the figure takes `tabular-nums` is a separate question. Where they leave open whether a figure in a label line, a row or a table cell takes `tabular-nums`, add it: it changes only the width of digits. Figures in running text need none. Where they ask for it but not on which element, put it on the element that holds the whole figure or label line, so that it covers every figure in it; a `<time>` inside inherits it. For a time inside a sentence, that is the `<time>` itself, not the paragraph.
- **Menus on small screens:** where the layout notes put the nav links behind a "Menu" button that opens a second `<nav>` in the header, the button is hidden from the notes' breakpoint up (`md:hidden` for `md`). Escape closes the menu while focus is on the button or in the menu, through one `onKeyDown` on the `<header>` that acts only while the menu is open, and focus then goes to the button. The second `<nav>` marks the current page's link the way the row does. It shares the row's `aria-label`, which is right, because one of the two is always hidden.
- **Counts:** a number with a noun reads right at one: "1 set", not "1 sets". Where the page brief gives the words for only one of the two, write the other the same way.
- **Sizes from data:** a height or a width that comes from data (a chart bar, a meter) is set with an inline `style`. That is the one use for an inline style.
- **Focus:** every link and control shows a 2px outline on keyboard focus: `focus-visible:outline-solid focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring`. Where a class list that the layout notes or the page brief spell out for a link, a nav link or a table's scroll box lacks them, add them to it. Keep `focus-visible:outline-solid` in it: in Tailwind 4 an `outline-none` on the same element, which stock components carry, otherwise hides the outline. An element that only gets focus from code (a heading or a message with `tabIndex={-1}`) gets the same outline written with `focus:` in place of `focus-visible:` (`focus:outline-solid focus:outline-2 focus:outline-offset-2 focus:outline-ring`): after a mouse click, a browser does not match `:focus-visible` on an element that code focuses. A link, a button or a field that code focuses keeps the `focus-visible:` classes it has: after a mouse click it shows no outline, which is how a browser treats every control, and is right. A stock component that ships its own focus ring (`Button`, `buttonVariants`, `Input`, `Textarea`, `Checkbox`, `Switch`, `RadioGroupItem`, `SelectTrigger`, the day buttons of a `Calendar`, `AccordionTrigger`, the close button of a `Sheet`) must lose that ring. Do it once, in the component's file in `components/ui`, which is yours to change: replace its `focus-visible:ring-*` classes with the outline classes, and in a field (an `Input`, a `Textarea`, a `SelectTrigger`, a `Checkbox`, a `Switch` or a `RadioGroupItem`) replace its `aria-invalid:ring-*` classes, the `dark:` ones included, with `aria-invalid:ring-0`, or a field with an error shows a tinted ring. `Button` has two more sets. Its base classes also carry `aria-invalid:ring-*` classes, the `dark:` one included: replace them with one `aria-invalid:ring-0`, as in a field. Its `aria-invalid:border-destructive` and `dark:aria-invalid:border-destructive/50` are borders and stay: what the notes say about a field's border classes is for fields. Its `destructive` variant carries `focus-visible:ring-*` classes of its own, the `dark:` one included: delete them and put nothing in their place, because the base classes already give every variant the outline. That variant's `focus-visible:border-destructive/40` is a border and stays. Wherever this rule says replace, change the classes in the file and do not add `ring-0` beside them: an added class only wins where it comes later and passes through `cn`. The stock `focus-visible:border-ring` can stay. These ring changes go only into the files of components that this page uses and that can take focus on it: a `Badge` that is not a link keeps its ring classes. So does `button.tsx` on a page with no `Button` and no `buttonVariants` link. Its other edits still follow the notes: a hover change they make "on every page" is made here too, and the `cn` import from the setup steps goes into every file. A box that scrolls sideways (a code block, a wide table) gets `tabIndex={0}`, `role="region"`, an `aria-label` and the same outline, also at widths where it happens to fit. Where a focusable box touches the edges of a parent that has `overflow-hidden`, draw its outline inside it: `focus-visible:-outline-offset-2` in place of `focus-visible:outline-offset-2`.
- **Controls:** no control keeps the browser's own look, at rest or open. A choice from a list is the project's `Select`, never a native `<select>`, whose arrow and open list the browser draws. A date is picked from the project's `Calendar` in a `Popover`, never an `<input type="date">`. A checkbox, a radio button and a switch are the project's `Checkbox`, `RadioGroup` and `Switch`, never a bare `<input>`. Add a missing one with `npx shadcn@latest add <name>`. The theme's layout notes say how it styles each one. For one they do not cover, make it match the theme's `Input`: the same height, corner, border, fill, text size and focus outline, with its icon as far from the right edge as the text is from the left, and a popup on the theme's surface with a 1px `border-border`, the theme's corner and text in the type scale. Leave no stock text size, glow ring or translucent ring on it. Every `Textarea` gets `resize-none` as well as the classes the notes give it, so the browser draws no grip in its corner. The stock one grows with its text (`field-sizing-content`), and one the page brief sizes (`field-sizing-fixed` with `rows`) keeps that size. A field that searches or filters is an `Input` with `type="search"`, which tells a screen reader it is a search box. It also gets `[&::-webkit-search-cancel-button]:appearance-none`, which hides the clear button a browser draws in it. A `Select` takes its name from its visible label in two ways: the `<label>` has the `SelectTrigger`'s `id` as its `htmlFor` (the trigger is a `<button>`, so a click on the label reaches it), and the trigger has `aria-labelledby` with the label's `id`. Base UI links only its own `Select.Label`, which `select.tsx` does not wrap (its `SelectLabel` heads a group in the open list). A date field you write as a component takes a `ref` and passes it to its trigger, so code can focus it. The stock `CalendarDayButton` makes a `ref` and never attaches it, so add `ref={ref}` to its `<Button>`, or the arrow keys move nothing. End its classes with a `dark:data-[selected-single=true]:hover:` copy of the chosen day's fill and text classes (`dark:data-[selected-single=true]:hover:bg-primary dark:data-[selected-single=true]:hover:text-primary-foreground` for the stock ones): a `hover:` class loses to the chosen day's stock `data-[selected-single=true]:` classes, but a `dark:hover:` one beats them.
- **Not allowed:** purple or multi-color gradients; emoji used as icons or bullets; glows and colored shadows.
- **Avoid:** a card inside a card.
- **Dark mode:** the page must work with the `dark` class on `<html>`. Because every color comes from a semantic class, this needs no extra code; do not write `dark:` color overrides. A new shadcn project follows the system's mode and switches on the `d` key: leave that as it is, and add no mode switch of your own.

From the theme's own do's and don'ts:

- Do let the clay background show: most of a page is paper.
- Do use a terracotta fill once per screen, for the thing you want pressed.
- Do set prices and quantities in the mono font.
- Don't use pure black or pure white. The ink is brown and the paper is clay.
- Don't use gradients, glows or drop shadows on cards.
- Don't introduce a color, size or radius that is not a token above.

## Check before you finish

Build the project, then measure it against the theme with Strict Check:

```bash
npx @strictthemes/check --dist dist
```

`dist` is the folder the build wrote. Add `--path /pricing` for each page you touched other than `/`. Fix every error it lists by using a value the theme allows, and run it again until the last line starts with `Passed`. Do not mark code `strict-ignore` to get there.

Then tell the user what you built, what the check reported, and anything you could not verify.
