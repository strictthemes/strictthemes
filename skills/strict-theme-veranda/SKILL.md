# Veranda

A warm, unhurried theme for guesthouses, small hotels and places to stay. Cream paper, slate ink, and clay, sage and sand used sparingly.

This skill is for building UI in the Veranda theme: a page, a section or a component. `DESIGN.md` decides the tokens: colors, type, spacing steps and corners. The notes below say how the theme lays a page out and which token goes where.

## Before you start

1. **Check the theme is installed.** The project should have `DESIGN.md` in its root and the Veranda variables in its global CSS. If not, run `npx shadcn@latest add https://strictthemes.com/r/veranda.json` and save https://strictthemes.com/themes/veranda/DESIGN.md as `DESIGN.md` in the project root. In a project without shadcn, use https://strictthemes.com/themes/veranda/tailwind.css instead. If the global CSS still imports a font the theme does not use (a new shadcn project imports Geist), remove that import, and uninstall its package if nothing else uses it. Keep every font import the theme's install added, also one for a style no page uses yet.
2. **Read `DESIGN.md` from start to finish.** It is the source of truth for every visual decision.
3. **Look at the project before writing code.** Use its framework, router and file layout. For controls (buttons, inputs, tabs, menus, dialogs, accordions, data tables) use the components in `components/ui`, and add a missing one with `npx shadcn@latest add <name>` rather than writing your own, unless the page brief names a plain element. Layout is plain elements with theme classes: sections, panels, figures and lists need no component.
4. **Teach `cn()` the theme's type classes.** shadcn's class merger does not know `text-display` or `text-h1`. It takes them for colors, so `cn("text-label text-muted-foreground")` silently drops one of the two, and a type class passed to a stock component does not replace its size. In a new shadcn project, `lib/utils.ts` only passes `cn` on from the `cn` package. Unless the file already holds the lines below, change it to:

   ```ts
   import { createCn } from "cn/config"

   // The theme's type classes are font sizes, not colors.
   export const cn = createCn({
     extend: {
       classGroups: {
         "font-size": [{ text: ["display", "h1", "h2", "body", "label"] }],
       },
     },
   })
   ```

   Then make every file in `components/ui` use it: where one has `import { cn } from "cn"`, change that line to import `cn` from the project's utils file (`@/lib/utils` in a default setup). Do the same for each component you add later. If the project uses `tailwind-merge` instead of the `cn` package, its components already import from the utils file: pass the same object to `extendTailwindMerge` and keep `clsx`.

## The theme in short

- **Fonts:** Cormorant for headings, Outfit for body text, Cutive Mono for labels and code.
- **Type scale** (size/weight; each class also sets line height and tracking): `text-display` 68px/500, `text-h1` 44px/500, `text-h2` 28px/600, `text-body` 16px/400, `text-label` 13px/400.
- **Font per size:** a type class does not set the font family. Headings (`<h1>` to `<h6>`) get the heading font on their own; on any other element add the font class: `font-heading` with `text-display`, `text-h1`, `text-h2`; `font-mono` with `text-label`.
- **Spacing scale**, with the Tailwind step in brackets: 4px (`1`), 8px (`2`), 16px (`4`), 24px (`6`), 48px (`12`), 104px (`26`).
- **Corners:** `rounded-sm` 2px, `rounded-md` 4px, `rounded-xl` 12px (the `lg` corner in `DESIGN.md`). `rounded-lg` is 4px as well: it is shadcn's name for the base corner, the one its stock buttons and inputs use.
- **Colors (light mode):** primary #3D405B, on-primary #F4F1DE, secondary #F2CC8F, on-secondary #2A2C40, tertiary #81B29A, on-tertiary #2A2C40, neutral #5C5F78, background #F4F1DE, surface #FBFAF1, foreground #2A2C40, border #DDD8BD, error #A63A24, clay #E07A5F, on-clay #2A2C40.

The layout notes below are written around a sample organisation and its pages. If the user gave you their own product, its name, pages and content replace the sample's, and the layout, the colors and the classes stay as the notes give them.

### How Veranda pages are laid out

- **The clay block:** every page has exactly one block of clay, where the page brief puts it, and nothing else on the page is `bg-clay`. The block is a plain element with `rounded-xl bg-clay p-6 text-clay-foreground`, the fill and the ink always together on the block itself, with no border and no shadow. Clay and its ink are the same in both modes, so the ink class keeps text on clay dark (`#2A2C40`) in dark mode too. Everything inside the block inherits the ink: no element in it gets a text color class of its own, so never `text-foreground`, `text-muted-foreground` or `text-primary` there, also not on the labels, dates and prices that the notes below make muted elsewhere. The block holds a heading and a few facts as text, and nothing that takes focus or carries its own color: no link, button, field, error line, badge, card or picture. In dark mode the main button and the focus outline are sand, which hardly shows on clay; the action that goes with the block sits on the paper, beside it or right after it. An icon in the block draws in the ink on its own. The block has no rules inside it: its parts are set apart by the margins of the rhythm note. Never a clay block inside a card.
- **Container:** one `<div>` wraps the whole page and is the container: `mx-auto max-w-[1160px] px-4 md:px-6`, plus `text-body`. This width is the one arbitrary value allowed. Inside it sit the `<header>`, a `<main>` holding everything between the two, and the `<footer>`.
- **Grid:** where the page brief puts things side by side, they are items of a grid: `grid gap-6 md:grid-cols-12`, a single column below `md`. "Columns 1–7" is `md:col-span-7`; "columns 9–12" is `md:col-span-4 md:col-start-9`, and so on. The grid's `gap-6` is the space between its items in both directions, also when they stack, so a grid item never has a top margin. Pages are uneven on purpose: a picture of seven columns stands beside text of four, with the column between them empty. Leave the columns the page brief does not fill empty, and center nothing to fill them. Where the page brief says a section is "a grid", the `<section>` itself carries the grid classes beside its own; where it puts a section's content "in columns 1–7 of a grid", one `<div>` in that grid spans those columns and holds the content, and the `<section>` itself is that grid, unless the page brief says the section holds more after the grid, in which case the grid is a `<div>` of its own. Add `md:items-start` to a grid of two or more items, unless the page brief says how they line up; a grid of one item needs none.
- **Measure:** a paragraph of body text is at most `max-w-xl` wide (576px), however many columns it sits in. A heading may run wider.
- **Vertical rhythm:** written as a top margin on each element (`mt-*`), never as `space-y-*`, a bottom margin, or a gap on a stack of text. These are the only distances:
  - A heading under a label line, a label under the thing it belongs to (a caption under a picture, a line of facts under a name), a field under its label, and an error or helper line under its field: `mt-2`.
  - Text under a heading, and a paragraph after a paragraph: `mt-4`.
  - A block after text or after another block (a grid, a list, a table, a card, a form, a picture, the clay block, a button or a link on a line of its own): `mt-6`.
  - A new part inside a section that opens with its own heading, after other content: `mt-12`.
  - The first element inside any box (a section, a grid item, a card, the clay block, a list item, a form) has no top margin.
  - A link or a button on a line of its own sits in a `<p>` or a `<div>`, which carries the margin.
  These margins rely on normal block flow. Inside a grid item, a card or the clay block, do not make the content `flex flex-col` with a gap. Inside a flex row (the header, a label line with a badge, a group of buttons) the space is the row's `gap-*`, as the page brief states it. Where the page brief gives an element its own margin, it replaces the one from this list.
- **Sections:** `<main>` holds a stack of `<section>` elements, each with `aria-labelledby` pointing at its heading, or an `aria-label` where it has no heading of its own. The first has `pt-12` and no border: the header's hairline is above it. Every other section opens with one hairline and 104px of space above it: `mt-12 border-t border-border pt-6 md:mt-26` (48px above the line on a phone). The one exception is a section that the page brief says is the clay block itself or holds nothing but it and its action: it has `mt-12 md:mt-26` and no border or padding, because the block needs no line. A `<section>` nested inside another takes the margin the page brief gives it, never these classes.
- **Section heads:** where the page brief gives a section a label line, the line comes first, in `text-muted-foreground`, right under the hairline; then with `mt-2` the section's `<h2>`; then with `mt-4` a sentence or two where the page brief gives them.
- **Header:** the `<header>` is itself the row, with `border-b border-border py-6`: `flex flex-col items-start gap-4 md:flex-row md:items-baseline md:justify-between`. On the left the house's name, `Kittiwake House`, a link to `/` in `font-heading text-h2`, styled as a header link and never marked as the current page. It is not a heading element and has no weight class. On the right a `<nav>` with the `aria-label` "Main", the page's only `<nav>`, holding a `<ul>` with `flex flex-wrap gap-x-6 gap-y-2` and four `<li>`s, each one link as a label, in this order: "Rooms" (`/rooms`), "Menu" (`/menu`), "Find us" (`/#find-us`) and "Reserve" (`/reserve`). Every link to these places uses these addresses. Below `md` the links sit under the name; the four fit on one line at 375px, so there is no "Menu" button. Mark one link as current only where the page brief names it.
- **Footer:** a `<footer>` with `mt-12 border-t border-border py-12 md:mt-26`. Inside it a grid (`grid gap-6 md:grid-cols-12 md:items-start`) with two parts, then one line:
  - Columns 1–5 (`md:col-span-5`): the house's name as a `<p>` in `font-heading text-h2` (not a heading, not a link), then with `mt-2` one sentence in `text-body`: "Six rooms above the harbour at Port Lowan, with breakfast on the veranda."
  - Columns 8–12 (`md:col-span-5 md:col-start-8`): an `<address className="not-italic">` in `text-body` holding two block `<span>`s, `9 Harbour Terrace` and `Port Lowan LW6 3QT`; then, outside the `<address>`, with `mt-4` a `<p>` holding the telephone number `01632 960 352` as a link to `tel:+441632960352`, and with `mt-2` a `<p>` holding `stay@kittiwakehouse.example` as a link to `mailto:stay@kittiwakehouse.example`. Both are footer links in `text-body`.
  - Under the grid, with `mt-6`, a `<p>` label in `text-muted-foreground`: `© 2027 Kittiwake House · Open all year`.
- **The house:** every page is about the same invented guesthouse, and uses these facts word for word. Kittiwake House, 9 Harbour Terrace, Port Lowan LW6 3QT, an invented harbour town on a south-facing bay. Built in 1894 as the harbour pilot's house, with a glazed veranda across its front where breakfast is served; kept by Nell Carrow and Jonah Pike since 2016. Telephone `01632 960 352`, email `stay@kittiwakehouse.example`. Six rooms, open all year. Guests arrive from 15:00 to 20:00 and leave by 10:30. Breakfast is included in every price and served from 08:00 to 10:00, on Sundays until 10:30. Supper is served from Thursday to Saturday, from 18:30 to 20:30, to guests who ask by 14:00. In July and August a stay is two nights or more. A price is for the room for one night, whatever the number of guests it sleeps, and depends on the season of that night: winter (1 November to 31 March), spring and autumn (1 April to 30 June, and 1 September to 31 October), summer (1 July to 31 August). The rooms, from the ground floor up, each with its address, floor, bed, size, view, the number it sleeps and its three prices (winter, spring and autumn, summer):
  - Thrift (`/rooms/thrift`): ground floor, double bed, 16 m², garden view, sleeps 2; £104, £124, £146.
  - Campion (`/rooms/campion`): first floor, single bed, 11 m², garden view, sleeps 1; £78, £92, £108.
  - Samphire (`/rooms/samphire`): first floor, twin beds, 18 m², harbour view, sleeps 2; £112, £132, £156.
  - Marram (`/rooms/marram`): first floor, king bed, 22 m², sea view, sleeps 2; £128, £152, £178.
  - Sea Holly (`/rooms/sea-holly`): second floor, king bed and a daybed, 24 m², sea view, sleeps 3; £142, £168, £196.
  - Tamarisk (`/rooms/tamarisk`): second floor, king bed and two singles, 31 m², harbour view, sleeps 4; £164, £192, £224.
  A room's "from" price is its winter price: `From £128 a night`. Only Marram has a page: a link to any other room points to `#`.
- **Headings:** the `<h1>` is `text-h1`, and `text-display` from `lg` up where the page brief says so (`text-h1 lg:text-display`). A section's `<h2>` is `text-h2 md:text-h1`. An `<h3>` or `<h4>` in the heading font is `text-h2`. Headings get the heading font on their own; any other element in `text-display`, `text-h1` or `text-h2` adds `font-heading`. Nothing in the heading font is smaller than `text-h2`: a smaller heading is a label heading. Sentence case, no full stop.
- **No bold:** Cormorant is never bold. A type class already gives a heading its weight, so no heading and no text in `font-heading` gets a weight class: never `font-bold`, `font-semibold` or `font-medium`. A browser makes `<strong>` and `<b>` bolder than the text around them, so neither goes into a heading or into text in the heading font: mark a phrase there with a plain `<span>`. If the user's own heading comes with a `<strong>` or a `<b>` that has to stay, give it the weight of its heading, so it does not thicken: `font-medium` inside `text-display` or `text-h1`, `font-semibold` inside `text-h2`. Body text and labels have no bold either: no `<strong>`, no `<b>` and no weight class on them. A `<th>` is bold in a browser too: every header cell gets `font-normal`.
- **Italic:** the italic of the heading font is the theme's one flourish, and it is installed. It is set with the `italic` class on a `<span>` around one phrase of a heading, or on a guest's own words set in `font-heading`. At most one phrase in a heading, and only where the page brief names it; at most two italics on a page. Nothing else is italic: Outfit and Cutive Mono have no italic here and a browser would only slant them, so no `<em>`, `<i>` or `<cite>` in body text or labels, and every `<address>` gets `not-italic`.
- **Labels:** nav links, form labels, the lines of facts about a room, floors, dates, times, prices, captions, table headers, terms in a `<dl>`, and button and badge text are labels: `font-mono text-label uppercase`. The wide tracking comes with `text-label`; add no `tracking-*` class. A label is a short fragment, not a sentence. Helper text, error lines and any line the page brief writes as a sentence use the label's font and size but are not uppercased. Parts of a label line are joined with ` · `. A label on its own line is a block element such as a `<p>`. An email address is never uppercased: inside a label it sits in a `<span>` (or its link gets) `normal-case`.
- **Label headings:** a heading styled as a label (Getting here, To start, Check your dates) is the heading element that keeps the heading order, with `font-mono text-label uppercase text-foreground`. Keep the `font-mono`: a heading element gets the heading font on its own.
- **Text color:** headings, label headings, body text, names, form labels, nav links, the line of facts about a room, a total and a menu price are `text-foreground`, except on the clay block, where they take its ink and have no color class. Captions, floors, dates, a price per night, `<dt>` terms, the label line that opens a section, helper text and the footer's © line are `text-muted-foreground`. Muted text sits only on `bg-background` or `bg-card`. Paragraphs are never muted. A button's or a badge's text color comes from its variant or its classes, and text on the clay block from the block. No other text colors: slate (`primary`), sand, sage and clay are never text colors.
- **Dates and times:** a date or a clock time is a `<time>` with a `dateTime` wherever it appears, in a sentence, a label or a row too, except in a choice of a `Select`: `<time dateTime="2027-05-14">Friday 14 May 2027</time>`, `<time dateTime="08:00">08:00</time>`. A date is written with the weekday, the day, the month in words and the year, with no comma (`Friday 14 May 2027`), or without the weekday where the page brief shows it so (`1 April 2027`). A clock time is 24-hour with two-digit hours: `08:00`, `18:30`. In a label or a row, a span of hours is two `<time>` elements joined by an en dash, `08:00–10:00`; in a sentence it reads "from 15:00 to 20:00", each time a `<time>`. A season's dates without a year (`1 November to 31 March`) and the copyright year are plain text. "Today" is always the visitor's own clock, never a sample date.
- **Prices:** a room's price is in whole pounds, `£128`; a menu price has two decimals, `£9.50`. A price is a label with `tabular-nums`: a price per night in `text-muted-foreground` (`From £128 a night`), a menu price or a total in `text-foreground`. A price is set large, in `font-heading text-h1` or `font-heading text-h2`, only where the page brief says so.
- **Nights, guests and rooms:** a count is written with its noun, and reads right at one: `1 night`, `2 nights`; `1 guest`, `2 guests`; `1 room`, `2 rooms`.
- **Links:** a link in running text is `text-foreground underline decoration-1 underline-offset-4 hover:text-muted-foreground`, and inherits its size and font. A link in the header or the footer, and a name that is a link, is `text-foreground decoration-1 underline-offset-4 hover:underline`; the link for the current page has `aria-current="page"` and `underline`. Links are never colored, and get `transition-colors duration-150`. A link whose destination the page brief and these notes do not give points to `#`.
- **Onward links:** a link that stands alone at the end of a part ("See Marram", "See the menu") is a `<p>` holding the link, a label (`font-mono text-label uppercase`) styled as a link in running text, in `inline-flex items-center gap-2`, with the `ArrowRight` icon after the words. Its words say where it goes: "See Marram", never "Read more".
- **Added components:** a component you add with `npx shadcn@latest add` during the build (an `Input`, a `Textarea`, a `Select`, a `Popover`, a `Calendar`, a `Badge`, a `Table`) gets the `cn` import, the focus outline only if it takes focus on the page, and the edits these notes give its file.
- **Buttons:** the shadcn `Button` with `className="h-auto rounded-md px-6 py-2 font-mono text-label font-normal uppercase"`: `font-normal` because the typewriter face has one weight. The default variant (slate, sand in dark mode) is for the page's one main action: the page brief names it, and no page has two. Every other button is `variant="secondary"` (sand, a lighter slate in dark mode). Its stock hover can hardly be told from its resting color: in `components/ui/button.tsx`, replace the `secondary` variant's `hover:bg-[color-mix(in_oklch,var(--secondary),var(--foreground)_5%)]` with `hover:bg-secondary/80`, once, not beside it, on every page, so each page's `button.tsx` is the same. The unchosen buttons of a button group are `variant="outline"`; on a page that has a button group, and only there, in the `outline` variant replace `border-border` with `border-muted-foreground` and delete `dark:border-input`, so their outline is as clear as a field's. Do not use the `ghost`, `link` or `destructive` variants, or the `xs`, `sm` or icon sizes. A button that sends a form needs `type="submit"`: this `Button` is `type="button"` unless told otherwise. A call to action that goes to another page, or a `mailto:` link styled as a button, is an `<a>` with the same classes: write `cn(buttonVariants({ variant }), "h-auto rounded-md px-6 py-2 font-mono text-label font-normal uppercase")`, because `buttonVariants` alone does not merge classes. Button text is two or three words, with no icon.
- **Button groups:** a set of buttons where one is chosen (a filter) is a `role="group"` with an `aria-label` and `flex flex-wrap gap-2`. The chosen button has `aria-pressed="true"` and `variant="secondary"`; the rest have `aria-pressed="false"` and `variant="outline"`. Not `Tabs`: there are no tab panels.
- **Inputs:** the shadcn `Input` with `className="h-11 rounded-md px-4 text-body md:text-body"` (44px tall), and the shadcn `Textarea` with `className="min-h-24 rounded-md px-4 py-2 text-body md:text-body"`. Their border is slate-grey and their fill is the card's, in both modes: in `components/ui/input.tsx` and `components/ui/textarea.tsx`, replace `border-input` with `border-muted-foreground`, replace the stock `bg-transparent` and `dark:bg-input/30` with `bg-card` (in `input.tsx`, `file:bg-transparent` stays), and delete `dark:aria-invalid:border-destructive/50`, so a field's error border matches the select's in dark mode. The stock `focus-visible:border-ring` and `aria-invalid:border-destructive` stay. Every field has a visible `<label>` above it with `block`, a label in `text-foreground`, tied to it with `htmlFor`, and the field has `mt-2`. A field that may be left empty says so in its label: `Phone (optional)`. A date is never an `Input` of type `date`: see the Date fields note.
- **Selects:** a choice from a short list is the shadcn `Select`; add it with `npx shadcn@latest add select`. Never a native `<select>`: the browser draws that one and its open list, and no control here keeps the browser's look. Write `<Select items={…} value={…} onValueChange={…}>` around `<SelectTrigger><SelectValue /></SelectTrigger>` and a `<SelectContent>` that holds one `<SelectItem value="…">` per choice directly, with no `SelectGroup`. `items` is the list of the choices as `{ value, label }`: without it the trigger shows the value, not the label, where the two differ. `onValueChange` gets the new value, not an event, and its type allows `null`: ignore a `null`. Unless the page brief says it starts on a value, a select starts with the value `null` and its list has no empty choice: the trigger then shows a placeholder in words, `<SelectValue placeholder="Choose a room" />`, which the stock `data-placeholder:` class sets in `text-muted-foreground`. A choice is plain text. The trigger fills its parent and gets `className="mt-2"`. It gets the same label and error handling as any field: the `<label>`'s `htmlFor` is the `id` on the `SelectTrigger`, `aria-invalid` and `aria-describedby` go on the `SelectTrigger` too, and code that moves focus to the field focuses the trigger. In a form that the browser sends, `name` goes on the `Select`, which sends the value in a hidden input. Edit `components/ui/select.tsx`, once, changing the classes in the file, so that the trigger looks like an `Input` and the open list is the theme's:
  - `SelectTrigger`: replace `w-fit` with `w-full`, its two stock gaps (its own and the one in `*:data-[slot=select-value]:`) with `gap-2`, `border-input` with `border-muted-foreground`, `bg-transparent` with `bg-card`, its stock paddings (`py-2` and the two side paddings after it) with `px-4`, its small text size with `text-body`, `data-[size=default]:h-8` with `data-[size=default]:h-11`, its `focus-visible:ring-*` classes with the outline classes of the Focus rule, and its `aria-invalid:ring-*` classes, the `dark:` one included, with `aria-invalid:ring-0`; delete `dark:bg-input/30`, `dark:hover:bg-input/50` and `dark:aria-invalid:border-destructive/50`, as in the `Input`. Give the `ChevronDownIcon` in it `strokeWidth={1.5}` and add `-mr-1` to its classes: the chevron is drawn 4px inside its 16px box, so its tip then ends 16px from the border, as far as the text starts from the left one.
  - `SelectContent`: change the default `align = "center"` to `align = "start"` and `alignItemWithTrigger = true` to `alignItemWithTrigger = false`, so that the list opens under the trigger, not over it. On the popup, replace `w-(--anchor-width) min-w-36` with `max-w-(--available-width) min-w-(--anchor-width)`, which makes the list as wide as its trigger and wider only where a choice needs it, and replace `ring-1 ring-foreground/10` with `border border-muted-foreground py-2`: the list has the slate-grey outline of the field it hangs from, because a hairline in `border-border` hardly shows on a card in dark mode. Its 4px corner, `bg-popover` (the card's cream) and `shadow-md` stay.
  - `SelectItem`: replace its stock gap with `gap-2`, its three paddings with `py-2 pr-12 pl-4` and its small text size with `text-body`; delete `rounded-md`; replace its two `focus:` color classes with `focus:bg-secondary focus:text-secondary-foreground` and delete the class that starts with `not-data-[variant=destructive]:focus:`; on the `<span>` around the `CheckIcon`, replace `right-2` with `right-3`; give the `CheckIcon` `strokeWidth={1.5}`. A row then runs the full width of the list with its text under the trigger's text; the row under the pointer or the arrow keys is sand, like a button at rest, and the chosen row has a check in the ink under the trigger's chevron.
  - Parts these pages do not show: in `SelectLabel`, replace the two paddings and the small text size with `px-4 py-2 font-mono text-label uppercase`; in `SelectSeparator`, replace its two margins with `my-2`.
- **Date fields:** a date is picked from the shadcn `Calendar` in a `Popover`, never an `Input` of type `date`, whose picker the browser draws; add them with `npx shadcn@latest add popover calendar`. Write one component, `components/ui/date-picker.tsx`, and use it for every date field: `<DatePicker id="arrive" labelId="arrive-label" name="arrive" value={arrive} onValueChange={setArrive} min={today} className="mt-2" />`, which also takes `aria-invalid` and `aria-describedby` and passes them, with `className`, to its trigger. `value` is the date as a date field holds it, `2027-05-14`, or an empty string while no day is chosen; `onValueChange` gets the same string, and `min`, the first day that can be chosen, is one too. Inside, such a string becomes a `Date` with `new Date(year, month - 1, day)` and a `Date` a string from its own year, month and day, never through `toISOString`, which would move a day in some time zones. Its parts:

## Rules

- **Colors:** only the theme's colors, through the semantic classes (`bg-background`, `text-foreground`, `bg-card`, `bg-primary`, `text-primary-foreground`, `text-muted-foreground`, `border-border` and so on). No hex, rgb or named colors in components, and no Tailwind palette classes such as `bg-blue-500` or `text-gray-600`.
- **Spacing:** padding, margin and gap use only the scale's steps (`1`, `2`, `4`, `6`, `12`, `26`) plus 0, 1px and 2px. No arbitrary values such as `p-[18px]`, and no other steps such as `p-3` or `gap-5`. `auto` margins are fine. Widths and heights such as `w-64` or `size-4` are sizes, not spacing. This applies to the code you write: a stock component keeps the spacing inside it, unless the page brief changes it. That includes the stock `gap-1.5` between a `Button`'s icon and its words: leave it, and add no gap class to the button.
- **Type:** every piece of text you write gets its size from one of `text-display`, `text-h1`, `text-h2`, `text-body`, `text-label`, set on the element or on a parent it inherits from. Put `text-body` on the outermost element of the page you write. No other sizes. A stock shadcn component keeps the size it ships with, unless `DESIGN.md` or the page brief gives that component its own style. A type class does not replace a weight class: where a stock component ships `font-medium` and the text should be regular, add `font-normal`.
- **Fonts:** only the theme's fonts, through `font-sans`, `font-heading` and `font-mono`. Do not add a font.
- **Corners:** only the `rounded-*` classes, which the theme already sets. No arbitrary radius. This theme has no full rounds: do not use `rounded-full`, and give a small mark a corner under half its height or none, because a box whose corner is half its height or more is a full round however it is written.
- **Contrast:** all text meets WCAG AA against its background.
- **Stock components:** a component from `components/ui`, and an `<a>` styled with `buttonVariants`, keeps the hover, pressed and disabled colors and the motion it ships with, unless the page brief changes them, also where the layout notes give links a transition. They are the theme's colors under other names. The same holds for every other stock class that neither the notes nor the page brief name, also in a file you edit: it stays. Examples are `TableHead`'s `h-10`, `font-medium` and `whitespace-nowrap`, a `Checkbox`'s `dark:bg-input/30`, and the `group-has-[:focus-visible]/field-label:` classes, which only act inside a shadcn `Field`. Classes the notes give a stock component go in its `className` where you use it, unless they say to change its file. `TableCell`'s stock `p-2` then stays beside the `px-*` and `py-*` you pass, which is fine: those win.
- **Forms:** a typed value is trimmed at both ends before it is checked and before it is shown again, so a field of spaces is empty. A field's error line comes after its helper text, and its `aria-describedby` names the helper text first. A group with an error names its error line in its own `aria-describedby`. A radio group takes `aria-invalid` on its `RadioGroup`; a set of checkboxes takes it on each `Checkbox`, because a `<fieldset>` does not take it.
- **Long words:** text whose length the page does not control, such as an email address or a name the visitor typed and the page shows back, or a URL, gets `wrap-break-word` on its element. Otherwise one long word can widen its column past 375px.
- **Dates and figures:** where the layout notes and the page brief leave a case open, a `<time>` wraps only the date or the time, not the words around it. A date or a time inside a sentence is then plain text, and so is a copyright year. Where they ask for `tabular-nums` but not on which element, put it on the element that holds the whole figure or label line, so that it covers every figure in it; a `<time>` inside inherits it.
- **Menus on small screens:** where the layout notes put the nav links behind a "Menu" button that opens a second `<nav>` in the header, the button is hidden from the notes' breakpoint up (`md:hidden` for `md`). Escape closes the menu while focus is on the button or in the menu, through one `onKeyDown` on the `<header>` that acts only while the menu is open, and focus then goes to the button. The second `<nav>` marks the current page's link the way the row does. It shares the row's `aria-label`, which is right, because one of the two is always hidden.
- **Counts:** a number with a noun reads right at one: "1 set", not "1 sets". Where the page brief gives the words for only one of the two, write the other the same way.
- **Sizes from data:** a height or a width that comes from data (a chart bar, a meter) is set with an inline `style`. That is the one use for an inline style.
- **Focus:** every link and control shows a 2px outline on keyboard focus: `focus-visible:outline-solid focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring`. Where a class list that the layout notes or the page brief spell out for a link, a nav link or a table's scroll box lacks them, add them to it. Keep `focus-visible:outline-solid` in it: in Tailwind 4 an `outline-none` on the same element, which stock components carry, otherwise hides the outline. An element that only gets focus from code (a heading or a message with `tabIndex={-1}`) gets the same outline written with `focus:` in place of `focus-visible:` (`focus:outline-solid focus:outline-2 focus:outline-offset-2 focus:outline-ring`): after a mouse click, a browser does not match `:focus-visible` on an element that code focuses. A link, a button or a field that code focuses keeps the `focus-visible:` classes it has: after a mouse click it shows no outline, which is how a browser treats every control, and is right. A stock component that ships its own focus ring (`Button`, `buttonVariants`, `Input`, `Textarea`, `Checkbox`, `Switch`, `RadioGroupItem`, `SelectTrigger`, the day buttons of a `Calendar`, `AccordionTrigger`, the close button of a `Sheet`) must lose that ring. Do it once, in the component's file in `components/ui`, which is yours to change: replace its `focus-visible:ring-*` classes with the outline classes, and in a field (an `Input`, a `Textarea`, a `SelectTrigger`, a `Checkbox`, a `Switch` or a `RadioGroupItem`) replace its `aria-invalid:ring-*` classes, the `dark:` ones included, with `aria-invalid:ring-0`, or a field with an error shows a tinted ring. `Button` has two more sets. Its base classes also carry `aria-invalid:ring-*` classes: replace them with `aria-invalid:ring-0`, as in a field. Its `aria-invalid:border-destructive` and `dark:aria-invalid:border-destructive/50` are borders and stay: what the notes say about a field's border classes is for fields. Its `destructive` variant carries `focus-visible:ring-*` classes of its own, the `dark:` one included: delete them and put nothing in their place, because the base classes already give every variant the outline. That variant's `focus-visible:border-destructive/40` is a border and stays. Wherever this rule says replace, change the classes in the file and do not add `ring-0` beside them: an added class only wins where it comes later and passes through `cn`. The stock `focus-visible:border-ring` can stay. These ring changes go only into the files of components that this page uses and that can take focus on it: a `Badge` that is not a link keeps its ring classes. So does `button.tsx` on a page with no `Button` and no `buttonVariants` link, even where the notes change that file for a hover. The `cn` import from the setup steps is another matter and goes into every file. A box that scrolls sideways (a code block, a wide table) gets `tabIndex={0}`, `role="region"`, an `aria-label` and the same outline, also at widths where it happens to fit. Where a focusable box touches the edges of a parent that has `overflow-hidden`, draw its outline inside it: `focus-visible:-outline-offset-2` in place of `focus-visible:outline-offset-2`.
- **Controls:** no control keeps the browser's own look, at rest or open. A choice from a list is the project's `Select`, never a native `<select>`, whose arrow and open list the browser draws. A date is picked from the project's `Calendar` in a `Popover`, never an `<input type="date">`. A checkbox, a radio button and a switch are the project's `Checkbox`, `RadioGroup` and `Switch`, never a bare `<input>`. Add a missing one with `npx shadcn@latest add <name>`. The theme's layout notes say how it styles each one. For one they do not cover, make it match the theme's `Input`: the same height, corner, border, fill, text size and focus outline, with its icon as far from the right edge as the text is from the left, and a popup on the theme's surface with a 1px `border-border`, the theme's corner and text in the type scale. Leave no stock text size, glow ring or translucent ring on it. Every `Textarea` gets `resize-none` as well as the classes the notes give it, so the browser draws no grip in its corner. The stock one grows with its text (`field-sizing-content`), and one the page brief sizes (`field-sizing-fixed` with `rows`) keeps that size. A field that searches or filters is an `Input` with `type="search"`, which tells a screen reader it is a search box. It also gets `[&::-webkit-search-cancel-button]:appearance-none`, which hides the clear button a browser draws in it. A `Select` takes its name from its visible label in two ways: the `<label>` has the `SelectTrigger`'s `id` as its `htmlFor`, and the trigger has `aria-labelledby` with the label's `id`. Base UI links only its own `Select.Label`, which `select.tsx` does not wrap (its `SelectLabel` heads a group in the open list). A date field you write as a component takes a `ref` and passes it to its trigger, so code can focus it. The stock `CalendarDayButton` makes a `ref` and never attaches it, so add `ref={ref}` to its `<Button>`, or the arrow keys move nothing. End its classes with `dark:data-[selected-single=true]:hover:bg-primary dark:data-[selected-single=true]:hover:text-primary-foreground`: a `hover:` class loses to the chosen day's stock `data-[selected-single=true]:` classes, but a `dark:hover:` one beats them.
- **Not allowed:** purple or multi-color gradients; emoji used as icons or bullets; glows and colored shadows.
- **Avoid:** a card inside a card.
- **Dark mode:** the page must work with the `dark` class on `<html>`. Because every color comes from a semantic class, this needs no extra code; do not write `dark:` color overrides. A new shadcn project follows the system's mode and switches on the `d` key: leave that as it is, and add no mode switch of your own.

From the theme's own do's and don'ts:

- Do use clay once on a page, for one block.
- Do say prices per night, what is included and when to arrive plainly.
- Do leave room: a heading has an empty column beside it.
- Don't set Cormorant in bold, and don't set body text in it.
- Don't count down, flash "only 1 left" or press the guest in any other way.
- Don't use gradients, glows or a card inside a card.
- Don't introduce a color, size or radius that is not a token above.
